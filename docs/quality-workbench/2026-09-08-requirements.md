# DSH QA Workbench `0.6.0`—`1.0.0` 需求文档（历史草案）

> **已被替代：** 当前路线改为 `0.4.1` 兼容性 → `0.5.0` Panel → `0.6.0` Native QA Execution → `0.7.0` AI Quality Intelligence → `1.0.0` AI-Native QA Workbench。请从 `2026-09-15-requirements.md` 开始。

## 1. 项目决策

- 代码仓库、插件 ID、npm 包名继续使用 `dsh-qa`。
- 产品定位收束为：**DeepSeek Harness（DSH）Agent 的 QA 工作面板**。
- 目标用户是使用 DSH 完成测试工作的 QA / 测试负责人；面板提供便捷界面与操作，与 DSH 测试模式会话配合完成测试闭环。
- 不新建第二套前端、第二个仓库或第二套数据主模型；在既有看板、项目详情与质量域（0.2–0.5）上演进体验与工作流。
- 质量域能力基线为 `0.2–0.5`；本路线按产品体验版本推进 `0.6` → `1.0`。package/tag 的正式发布版本仍以 `package.json` 和 Release 记录为准，不把能力阶段号自动当作当前发布版本。

## 2. 背景与问题

前序质量域文档和实现状态记录覆盖了 `0.2`—`0.5` 的质量任务、受控执行、证据包与 PASS/WARN/BLOCK 计算门禁；正式 Release 前仍需按各版本 DoD 重新验证。当前主要缺口不在「再建一套测管」，而在：

1. **首屏行动不清晰**：指标、待办、日历、项目、AI 状态权重接近，QA 打开后不知道先做什么（见 `docs/ui-critique-zh.md`）。
2. **与 DSH 对话的衔接成本高**：材料流、下一步动作、会话绑定状态分散，常用操作仍要在对话里「自己想命令」。
3. **「测什么」缺少面板侧辅助**：变更范围到回归集的桥梁偏弱，依赖 QA 在对话中口头描述。
4. **交付决策可读性不足**：门禁、证据、追溯分散在多个 Tab，汇报与放行成本高。
5. **可日常依赖度**：空状态、错误恢复、新项目第一次怎么走、文档与迁移稳健性尚未达到 1.0。

## 3. 用户与场景

### QA / 测试负责人（主用户）

打开工作台 → 看「需要你处理」→ 进入项目 → 在 DSH 测试对话里推进分析/登记 → 在面板里确认计划、启动受控执行、看证据与门禁 → 人工审批或例外。

### 产品 / 项目负责人（只读偏多）

查看门禁结论、阻断原因、证据入口与交付报告，不做自动放行。

### 开发者（辅助）

提交变更后，通过面板或 DSH 会话看到建议测试范围与风险提示；不能在无证据时看到 PASS。

## 4. 版本范围总览

| 版本 | 主题 | 本版目标 |
| --- | --- | --- |
| `0.6.0` 行动台 | 打开就能做事 | 统一行动队列、质量实时刷新、关键跳转、Skills 路径可配置 |
| `0.7.0` 对话工作台 | DSH 测试对话更好用 | 下一步建议、材料回填、QA 快捷条、会话绑定清晰 |
| `0.8.0` 变更与回归 | 知道测什么 | 变更摘要→建议范围、回归集草稿、预览与看板徽标 |
| `0.9.0` 证据与交付 | 交付决策更好懂 | 门禁同屏、追溯矩阵、失败分类+人工 promote、报告可读 |
| `1.0.0` 稳定工作台 | 可日常依赖 | 主路径打磨、空状态/向导、迁移与文档齐套 |

## 5. 分版必须交付

### 5.1 `0.6.0` 行动台

- 首页「需要你处理」统一队列：至少覆盖逾期/临期里程碑、待审批 approval gate、computed gate `BLOCK`/`WARN`、失败或中断的受控 run（以现有 `stats`/`reminders`/质量 API 可聚合的事实为准）。
- 前端订阅并消费已有 SSE：`quality.task.updated`、`quality.test-run.updated`（以及既有 `quality.evidence.updated` / `quality.gate.updated`），减少手动刷新。
- 项目详情提供一键跳转：打开 DSH 测试对话视图、定位门禁 Tab、定位证据/质量任务相关区域。
- Skills 安装相关根路径改为环境变量配置（已有 `QA_SKILLS_ROOT` / `QA_SKILLS_SITE_ROOT` 时补齐默认文档与校验），去掉对个人机器目录硬编码的依赖假设；缺省路径行为需在文档中写清。

### 5.2 `0.7.0` 对话工作台

- 对话视图旁「下一步建议」条：基于当前项目看板阶段、待办队列与质量任务阶段给出 1–3 条可点击建议（建议可插入对话草稿或切换面板，不自动执行危险写操作）。
- 材料流条目支持点选回填到输入区，或给出对应 DSH tool / 技能提示文案。
- 常用 QA 快捷条：登记用例、创建质量任务、提门禁申请等（触发方式：插入提示词 / 打开面板表单 / 调用已有 API，保持现有工具白名单与 revision 规则）。
- 会话绑定状态显性展示：未绑定、已绑定、可切换；独立模式保持降级提示。

### 5.3 `0.8.0` 变更与回归

- 基于项目 `workspacePath` 与既有 `git-diff` 来源能力，提供**变更摘要 → 建议测试范围**（可写入质量任务 `testScope` 草稿或独立建议对象；最终生效需人确认）。
- 一键生成/更新 **回归集草稿**；确认后才调用现有 `createRegressionSet` 语义落库。
- 从质量任务进入回归执行预览的路径缩短（复用现有 run-preview / profile 约束）。
- 看板卡片展示风险/回归覆盖相关徽标（只读投影，不改变看板列语义）。

### 5.4 `0.9.0` 证据与交付

- 门禁结论页（或详情内专区）：阻断原因、可豁免项、例外、证据入口同屏。
- 需求 ↔ 用例 ↔ 证据（及可选门禁引用）简易追溯矩阵视图。
- 失败分析分类：至少 `regression | environment | test-bug | other`（命名以技术方案为准）；**promote 缺陷必须人工确认**。
- 交付报告与趋势在项目详情内可完整阅读（复用 `0.5` report/trend，不重算第二套 verdict）。

### 5.5 `1.0.0` 稳定工作台

- 主路径端到端打磨：首页 → 对话 → 质量任务/执行 → 门禁。
- 空状态、错误恢复路径与关键术语说明（中英文）。
- 新项目「第一次怎么走」轻量向导（不替代文档）。
- schema/迁移稳健性回归、README/AGENTS/质量文档与版本说明齐套；`npm test` 与 `git diff --check` 作为发布门槛。

## 6. 明确不做（整条 `0.6`—`1.0` 路线）

- 不引入生产 npm 依赖或新前端框架。
- 不实现跨宿主 MCP 平台化作为 1.0 必达项（可后置）。
- 不做 CI 云端调度、跨机分布式执行、自动发布。
- 不引入真实多用户 RBAC；`actorLabel` 仍不是认证用户。
- 不允许无受控证据产生 `PASS`；`imported-summary` 不能作 PASS。
- 不自动向外发缺陷系统提单；不让 AI 结论替代人工缺陷确认。
- 不替代 Jira/Git/CI 成为唯一系统。

## 7. 验收标准（跨版本）

1. 每一版均可独立发布：该版范围验收通过，且既有单元/API/E2E 回归不回退。
2. 面板动作与 DSH 工具写入均遵守字段白名单与 `expectedRevision`（新写路径）。
3. 独立模式：无 DSH 对话时相关能力降级提示明确，不伪造 session。
4. 中英文、空状态、错误状态同步处理。
5. 交付前运行 `npm run test:unit`、`npm run test:e2e`（或 `npm test`）与 `git diff --check`。

## 8. 产品目标与度量（定性）

- QA 打开工作台后，**60 秒内**能找到并进入「当前最该处理」的事项。
- 从「看到待办」到「在 DSH 对话中开始动作」的跳转不超过两次点击。
- 门禁 BLOCK 时，阻断原因与证据入口无需翻多个无关 Tab 即可看到。
- 1.0 后，新用户可在向导指引下完成一次最小闭环（建项 → 对话/任务 → 看门禁），无需阅读全部设计文档。
