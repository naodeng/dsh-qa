# dsh-qa UI 草稿修订说明（基于现有功能）

- 日期：2026-11-27
- 对象：`stitch_dsh_qa_workspace_redesign` 初版草稿
- 目标：把草稿修成「现有功能都有落点、没有假字段、可以进入实现」的版本
- 原则：**UI 跟随现有功能**；看板保留；完整 DSH 对话并入首页；暗色和英文必须支持；删除占位字段；不做「签字放行」

---

## 0. 先定 5 件事

| 已确认决策 | 对设计的要求 |
| --- | --- |
| 看板保留 | 增加一级「项目看板」页面；保留 6 列、拖拽改阶段、快速预览抽屉、进入完整详情 |
| 完整 DSH 对话不单独设页 | 首页右侧 Copilot 必须能展开为完整对话，覆盖现有模型、技能/命令、附件、停止、雷达、策略、会话恢复；补展开态和移动端全屏态 |
| 暗色 + 英文 | 7 个页面、看板、展开对话、所有弹窗和状态都要有 dark 和 EN；设计系统补 dark tokens 和英文文案 |
| 新字段是占位文案 | 第 4 节的删除清单全部移除；不得把占位数字写进设计规范 |
| 门禁没有「签字放行」 | 删除「签字 / 一键放行 / 确认交付」；只保留现有的门禁评估、门禁例外、人工审批（通过/驳回）、阶段流转到已发布 |

> 关于门禁：现有功能是「质量门禁评估（PASS / WARN / BLOCK）+ 门禁例外 + 人工审批门禁（通过/驳回）+ 项目阶段流转」。发布动作是看板拖到「已发布」或详情里改阶段，服务端会用门禁拦截。没有「签字」这个动作，也没有「一键放行」。

---

## 1. 整体思路（按这个顺序改）

1. **冻结功能基线**：先把现有页面、弹窗、状态和接口列成清单（见第 5 节），设计只做「有落点」的东西。
2. **定信息架构**：4 个一级导航；项目工作区是看板下钻页；看板保留；对话并入首页。
3. **先删，不先加**：把假字段、假动作、假数字全部删掉，避免设计围绕它们继续生长。
4. **按页面补 parity**：现有功能没有落点的，逐页补 UI（第 3 节「缺 / 增」）。
5. **再重设计视觉**：看板和工作区可以重新排版，但不改交互语义、不改字段。
6. **最后补横向能力**：暗色、英文、响应式、无障碍、空/加载/错误/断线/冲突状态。
7. **用验收清单回归**：按第 5 节逐项打勾，确保没有「看着有、其实没有」的功能。

## 2. 信息架构定稿建议

### 2.1 一级导航

```
测试首页（今日待办）
项目看板
日历排期
QA Skills
```

- **不再把「项目工作区」作为一级导航**。项目工作区是看板/首页项目卡片的进入页，标题旁放「← 返回项目看板」。
- 首页的项目卡片、看板的卡片、搜索结果都进入同一个项目工作区。
- 「DSH 对话」不再作为一级导航；首页右侧 Copilot 承担对话，展开后可用完整功能。

### 2.2 全局顶栏

所有页面共用同一个顶栏组件：

- 左：品牌、版本号（可点开版本记录）、返回 DSH（仅嵌入 DSH 时显示）
- 中：全局搜索（项目/迭代；Ctrl/⌘K）
- 右：连接状态、新建项目、新建迭代、设置
- 连接状态只表达三种：`DSH 测试模式`、`独立模式`、`连接异常`。不要用「Host 在线」同时指代 DSH 会话和执行 Host。
- 主题和语言放在设置里，顶栏不占位。

### 2.3 页面关系

```
测试首页 ──点击项目──> 项目工作区 ──返回──> 测试首页
项目看板 ──点击卡片──> 项目工作区 ──返回──> 项目看板
项目看板 ──快速预览──> 抽屉（10 个 tab）
首页 Copilot ──展开──> 完整对话（模型/技能/附件/雷达/策略）
```

## 3. 逐页四清单（缺 / 删 / 增 / 改）

> 「缺」= 现有功能在草稿里没有落点。  
> 「删」= 草稿里的占位字段、假动作、和现有模型冲突的内容。  
> 「增」= 为了补「缺」需要补画的 UI（不是新增业务功能）。  
> 「改」= 草稿已有，但结构/语义/交互要调整。

### 3.1 全局框架

**缺**
- 项目看板一级入口。
- 所有页面都能用的全局搜索。
- 所有页面都能用的设置、版本、返回 DSH。
- 最近项目入口。
- 真实的连接状态（DSH 测试模式 / 独立模式 / 连接异常）。
- 示例数据提示。

**删**
- 每页各写一套顶栏动作（搜索/新建/设置/Copilot 只在首页出现）。
- 「Host 在线」这个含糊状态。
- 「运行 Host」这个无上下文的全局动作。
- 「项目工作区」一级导航。
- 「决策台」等不一致的导航别名。

**增**
- 统一顶栏组件（含全局搜索、版本、设置、返回 DSH、新建项目/迭代）。
- 最近项目：首页一块，或可收起的左栏；不能丢。
- 连接状态组件：正常 / 独立 / 断线，带重试（对话有重试；SSE 自动重连）。
- 版本入口：版本号 + 新版本提示，打开发布记录。

**改**
- 导航从 5 项（含 DSH 对话）改成 4 项。
- 「项目工作区」改为看板下钻页。
- 统一页面标题：`测试首页` / `项目看板` / `日历排期` / `QA Skills`。
- 移动端把设置、新建、对话收进「更多」，不要直接隐藏。

### 3.2 测试首页（今日待办）

**缺**
- 示例数据提示 + 清理示例数据。
- 行动队列的完整列表和「行动台」。
- 行动类型：质量任务待确认、里程碑临期/逾期、流程提醒（草稿只画了门禁、P0、超时）。
- 迷你日历 / 当天议程（或等价的「今日窗口」，但不能丢日程入口）。
- 在办项目表：项目/迭代、阶段、风险/用例、最近活动、快速预览。
- DSH 全流程辅助摘要（启用/全流程/关闭数量、当前模型说明）。
- 最近动态。
- 完整 DSH 对话能力（见 3.8）。

**删**
- 待办前的复选框。行动队列没有「勾选完成」动作，条件解决后才会消失。
- 假编号、假百分比、假 P0、假时间、假命令、假附件名。
- Copilot 里的「一键签字放行」。
- 「审批人 / 签字 / 签名」。
- 项目卡片上的 `142/144`、`68/85`、`94/94`、`52/52`、`98.1%`（没有定义口径，先删；要保留必须写成可计算指标）。

**增**
- 「查看全部 / 打开行动台」。
- 在办项目表或可筛选的项目列表。
- 最近项目入口。
- 可展开的 Copilot：
  - 默认 360px 右栏：最近消息 + 输入框 + 当前项目。
  - 展开态：占 50% 或全宽，显示完整会话、模型选择、技能/命令、附件、停止、雷达、策略、新建对话。
  - 移动端：全屏 sheet。
- 示例数据提示。

**改**
- 待办按风险排序：P0/阻断 > 待审批 > 提醒；不要按「当前选中项目」排。
- 项目胶囊改成真实字段：`projectKey`、标题、项目/迭代、阶段、风险徽标、真实计数。
- 「今日窗口」去掉具体时间（现有日程只有日期，没有时间字段）。
- Copilot 的门禁摘要只保留「查看门禁 / 打开全链路」，不提供放行按钮。
- 首页的「今日待办」标题可以保留，但导航名建议用「测试首页」。

### 3.3 项目看板（需要重新设计 UI）

**缺**
- 整个看板页面。
- 6 列、卡片、拖拽、快速预览抽屉、空列、移动端布局。

**删**
- `_2` 里的「阶段看板」tab（如果看板恢复为一级页面，就不要在项目工作区里再放一个同名 tab）。
- 假计数、假风险、假项目名。

**增**
- 看板页：
  - 顶部：标题/说明 + 新建项目（现有）+ 可选新建迭代。
  - 6 列：需求分析、用例设计、用例评审、执行中、缺陷回归、已发布；列头显示标题、提示、数量。
  - 卡片：标题、项目/迭代、`projectKey`、阶段、风险徽标（逾期/临期）、真实计数（需求/用例/缺陷/里程碑/报告/待审批门禁）、最近 1–2 条材料、最近活动、AI 进行中标记、快速预览。
  - 拖拽：拖起态、目标列高亮、放下后调 `transition`；拖到「已发布」被门禁阻断时给出明确原因。
  - 快速预览：打开现有抽屉（10 个 tab：概览、质量任务、需求、用例、缺陷、里程碑、报告、知识、纪要、门禁）。
  - 点击卡片：进入项目工作区。
  - 空列、空项目、加载失败状态。
  - 移动端：阶段切换器 + 单列卡片，或横向分页；不要 6 列压缩。

**改**
- 视觉可以重新设计（卡片密度、列头、状态色、拖拽反馈），但交互语义保持不变。
- 卡片上的计数用中文标签，不用「需/里/例/缺/报/审」这种单字缩写；至少提供 tooltip。
- 看板滚动位置要保留（现版本有保存/恢复）。

### 3.4 项目工作区（6 个分区）

**缺**
- 头部动作：返回看板、打开 DSH 对话、项目文件、编辑项目、设置与语言、删除项目记录、更多。
- 分区 01：行动队列、4 个指标、需求覆盖概览、质量任务列表、近期动态、项目资料与设置（编辑/删除/成员/策略/工作区/阶段历史）。
- 分区 02：需求覆盖矩阵、覆盖状态、搜索/筛选、用例状态编辑、断链/未知状态、未关联用例、风险列、验收标准。
- 分区 03：质量任务列表 + 选中任务详情（接受标准、风险、范围、来源、决策）+ 关联计划/运行/证据/故障分析/回归集 + 执行配置 + Host 配置 + 项目级运行/记录 + 新建质量任务/计算回归集/新建故障分析/确认缺陷。
- 分区 04：缺陷状态流（open/fixing/verify/verified/closed）、环境/模块/频率/影响、复现/预期/实际、证据引用、详情展开、质量任务风险列表。
- 分区 05：项目级门禁摘要 + 任务级门禁评估 + 5 项 checks + 门禁例外 + 待审批门禁（通过/驳回）+ 交付报告 + 门禁趋势 + 报告版本 + 证据包（完整性/哈希/下载/清理）。
- 分区 06：待安排日程 + 历史日程 + 材料动态 + 知识 + 纪要。
- （可选）右栏检视器：选中用例/任务/缺陷/证据时显示对应字段和动作。

**删**
- 01–06 路线进度条、「路线第 2/6 步」「下一阶段」按钮。它们会被理解成工作流阶段，和项目状态冲突。
- 假字段：代码分支、PR、关联 Skill、Host 构建号、P0/P1 缺陷、项目级 RSK、审批人、签字、签名、门禁就绪 %、条件通过、沙箱、并发压测、混沌注入、单用例通过/耗时、单例复跑。
- 「确认签字放行 / 驳回阻断」审批框。
- 假 ID（REQ-104 / TC-208 / QT-019 / BUG-412 / EVD-304）。

**增**
- 6 个分区作为 tab（带计数），不要进度条。
- 头部动作。
- 每个分区的完整内容。
- 可选检视器：按实体显示字段，动作要上下文相关（用例→查看运行；任务→Host 执行；缺陷→查看证据；证据→下载）。

**改**
- 01 从「4 个假指标 + 静态事实」改成真实的项目概览。
- 02 从「需求卡片列表」改成覆盖矩阵（或至少矩阵 + 卡片两种视图）。
- 03 从「3 张任务卡」改成任务列表 + 选中任务详情。
- 04 从「缺陷卡片」改成缺陷工作流列表。
- 05 从「审批框」改成门禁评估/例外/审批/报告/趋势/证据。
- 06 从「静态活动流」改成日程 + 历史 + 材料 + 知识 + 纪要。
- 右栏检视器如果保留，不能一个模板套所有实体；标签和动作要按实体变化。

## 6. 数据与状态映射（防止再出现假字段）

### 6.1 可用的真实字段

| 设计区域 | 真实字段 |
| --- | --- |
| 项目 | `projectKey`、`title`、`kind`、`status`、`product`、`owner`、`members`、`summary`、`workspacePath`、`assistant`、`history`、`counts` |
| 需求 | `id`、`title`、`kind`、`statement`、`acceptance`、`links[].testcaseId/purpose`；覆盖状态由这些派生 |
| 用例 | `id`、`title`、`kind`、`priority`、`preconditions`、`steps`、`expected`、`risks`、`status`、`trace` |
| 缺陷 | `id`、`title`、`severity`、`status`、`environment`、`module`、`frequency`、`impact`、`steps`、`expected`、`actual`、`evidenceRefs` |
| 质量任务 | `id`、`title`、`stage`、`version`、`analysisOrigin`、`acceptanceCriteria`、`risks`、`testScope`、`sources`、`decisions` |
| 测试运行 | `id`、`status`、`executor`、`resultTrust`、`summary`、`updatedAt` |
| 证据包 | `id`、`state`、`integrity`、`manifestSha256`、`totalSize`、`items[].relativePath/type/mimeType/sha256` |
| 门禁 | `type`、`title`、`status`、`verdict`、`checks[].key/status/severity/explanation/waived/exception`、`decisions` |
| 报告 | `title`、`docType`、`status`、`versions[].content` |
| 日程 | `title`、`date`、`kind`、`note` |
| 里程碑 | `title`、`dueDate`、`kind`、`basis`、`done` |
| 技能 | `name`、`title`、`description`、`categoryId`、`installed`、`availableInRepository` |
| 对话 | 模型、消息、附件、命令、技能（来自 DSH 会话） |

### 6.2 状态枚举（设计必须按这些写）

- 项目阶段：`intake` 需求分析 / `design` 用例设计 / `review` 用例评审 / `execute` 执行中 / `regression` 缺陷回归 / `closed` 已发布
- 用例：`draft` 草稿 / `reviewed` 已评审 / `executed` 已执行
- 缺陷：`open` 待处理 / `fixing` 修复中 / `verify` 待验证 / `verified` 已验证 / `closed` 已关闭
- 质量任务：`intake` 信息收集 / `confirmation` 待确认 / `review` 评审中
- 测试运行：`queued` / `running` / `passed` / `failed` / `cancelled` / `timed-out` / `unknown` / `environment-error`
- Host 执行：`queued` / `running` / `passed` / `failed` / `cancelled` / `timed_out` / `provider_error` / `blocked` / `not_run`
- 门禁结论：`PASS` / `WARN` / `BLOCK`；人工审批：`pending` / `approved` / `rejected`
- 门禁 checks：`stale-evidence`、`verified-evidence`、`critical-test-result`、`critical-risk`、`medium-coverage`
- 证据：`state`（ready/finalizing/expired/integrity-failed）+ `integrity`（verified/failed/unknown）
- 风险：severity `critical/high/major/medium/minor/low/trivial`；assessment `confirmed/candidate/dismissed`；disposition `open/mitigated/accepted/closed/dismissed`
- 日程类型：event / milestone；kind 用现有 `EVENT_KIND` / `MS_KIND`

### 6.3 指标口径

- 不要再写 `142/144`、`68/85`、`94/94`、`52/52`、`98.1%`，除非定义公式并在 UI 上标注。
- 推荐直接用现有概览指标：需求覆盖（已关联用例的需求 / 总需求）、测试用例总数、未关闭缺陷、交付门禁、已验证证据。
- 门禁只显示 `PASS/WARN/BLOCK/未评估` + blockers，不要「就绪度 %」。

## 7. 暗色、英文、响应式、无障碍

### 7.1 暗色

- 所有页面、所有弹窗、所有状态都要有 dark 版本。
- 语义色要重新给 dark 值：primary、success、warning、error、surface、border、text、code block。
- 代码块/日志在 dark 下要保持对比度；证据 SHA、运行日志不能变成低对比。
- 主题三选一：system / light / dark；设置里可切换，刷新保留。

### 7.2 英文

- 所有文案走 i18n key，不允许硬编码中文。
- 设计稿至少给出英文版本或英文文案表；英文按 30–40% 文本膨胀预留空间。
- 日期、数字、相对时间按语言格式化。
- 导航、按钮、空态、错误、确认、状态名都要有英文。

### 7.3 响应式

- 断点：1440 / 1024 / 768 / 390。
- 看板：移动端单列 + 阶段切换，不压缩 6 列。
- 项目工作区：移动端左栏折叠，检视器底部 sheet，分区 tab 横向滚动。
- 日历：移动端议程模式。
- 对话：移动端全屏 sheet，输入框固定。
- 任何页面不得横向溢出。

### 7.4 无障碍

- tablist/tab/tabpanel 语义、方向键、`aria-selected`、`aria-controls`。
- 弹窗：焦点陷阱、Escape、焦点恢复、背景点击关闭。
- 所有图标按钮有 `aria-label`；关闭按钮是真 `<button>`。
- `:focus-visible` 清晰可见；支持 `prefers-reduced-motion`。
- 状态不能只靠颜色；配文字/图标。
- 12px 中文小字要复核；`text-outline` 在小字上对比度不足，建议加深。
- 拖拽要有键盘替代（详情里改阶段）。
