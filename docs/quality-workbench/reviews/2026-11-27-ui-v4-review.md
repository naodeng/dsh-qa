## 二、实现前必须修正的 6 个点

### 1. 900px 高度下对话输入框仍在首屏外

v4 首页仍是固定 `lg:h-[1024px]`。实测 1440×900：

```
copilot-input top = 978px
viewport height   = 900px
```

在 900 高的笔记本上，输入框仍然看不到。请把容器改成 `lg:h-screen` / `h-[calc(100vh-顶栏)]`，并补一张 900/768 高度的截图；这是最后一处会直接影响真实使用的布局问题。

### 2. 移动端证据 tab 只显示 2/5 项 checks

桌面证据表有 5 项；移动端 `md:hidden` 的 stacked cards 只有：

- `stale-evidence`
- `medium-coverage`

缺：

- `verified-evidence`
- `critical-test-result`
- `critical-risk`

移动端用户看不到 critical-risk 失败，却能看到「通过/驳回」按钮，存在误放行风险。必须补齐 5 项，或移动端直接复用桌面 table 的完整数据。

### 3. 英文仍然不是「支持」，只是少量标签切换

实测 `data-i18n` 覆盖：

| 页面 | `data-i18n` 数量 |
| --- | --- |
| 测试首页 | 32 |
| 项目工作区 | 28 |
| 设置 | 24 |
| Skills | 18 |
| 状态页 | 11 |
| 日历 | 0 |
| 看板 | 0 |
| 移动端 | 0 |

日历/看板/移动端没有语言切换；工作区/设置/Skills 只翻译导航和少量标题，表单标签、表头、状态、空态、错误仍然是硬编码中文。需要补完整英文文案表 + 英文截图，并检查 390px 下英文膨胀。

### 4. 执行配置的枚举还不符合现有模型

v4 的 3 步流程结构对了，但字段值仍不对：

| 设计 | 现有模型 |
| --- | --- |
| `provider: controlled-local` | `controlled-local` 是 `resultTrust` / 本地执行模式，不是 provider；provider 是 `browser-use / computer-use / mcp` |
| `capability: api-contract / web-e2e` | host capabilities 是 `navigate / interact / inspect / tool-call`；本地执行用 `executor` + `targetFiles` |
| `profile=prof_controlled_local` | execution profile ID 前缀是 `profile_`，不是 `prof_` |
| `hostExecution (controlled-local)` | 本地受控运行不等于 hostExecution；本地运行记 test run（`mode: local`），Host 运行才有 hostExecution |
| `target: staging-api · 300s` | target（origins/mcpTargets/targetFiles）和 timeout 是分开的字段 |

建议：

- 本地执行：`executor / targetFiles / timeoutMs`
- Host 执行：`profile / provider / capability / target / artifactPolicy / timeoutMs`
- 不要再把 `controlled-local` 当 provider。

### 5. 需求 kind 用了 `risk-point`，现有枚举是 `risk`

现有 `requirement.kind` 是 `functional / nonfunctional / risk / issue`；v4 的需求矩阵、卡片、筛选器和检视器都用 `risk-point`。如果直接实现，筛选会匹配不到现有数据。

改回 `risk`（显示为「风险点」），或明确新增 `risk-point` 枚举并迁移数据。

### 6. Skills 数据仍是示例，不是目录

v4 的 5 个技能里，`api-testing`、`test-strategy` 存在；`contract-testing`、`e2e-playwright`、`release-gate` 在真实目录里不存在。`查看 Skill 详情 →` 仍是 `#`。

另外，v4 删掉了 v3 的 Skills 状态预览，因此现在没有设计：

- 加载中
- 目录加载失败
- 空结果
- 不可安装原因

页面副标题写「从 /api/skills 动态加载」，但设计里没有这些状态。建议至少补 loading/error/empty 三张状态图，并用真实技能名/计数做示例。

## 三、P1 收口项

### 1. 日历

- 页面说明写「日程删除确认」，但 `deleteEvent` 立即删除，没有确认。
- 月历单元格只显示 `evs[0]`，一天多个事件时没有 `+N`，当前版本会显示「另有 N 项」。
- 图例/年/月/日期跳转/7 天周视图/接下来 30 天都已补，保留。

### 2. 移动端首页

- 「需要你处理 (3)」现在有「查看全部 →」；但「在办项目 (3)」仍只展示 1 条，没有「查看全部」或「打开看板」入口。
- 移动端顶栏没有搜索/设置；当前版本手机上有搜索入口。
- 移动端首页没有 AI/最近动态，只有 DSH 对话入口；可以接受，但要明确「移动端只做分诊」。

### 3. 全局顶栏

- 看板：搜索 modal + DSH 对话 + 新建项目/迭代，没有设置。
- 日历：搜索是跳回首页的链接，不是搜索 modal；只有新建项目，没有设置/新建迭代。
- Skills/工作区/设置：有搜索 modal + DSH 对话 + 新建 + 设置。
- 需要统一：搜索面板、DSH 对话、新建项目/迭代、设置、版本/发布记录。

### 4. 设置/弹窗

- 项目表单缺 `autoExtract`（自动提取）开关；现有 assistant 有该字段。
- 设置里没有 DSH 预设（qa / quality-control）状态，也没有兼容 DSH 版本/官网；当前设置页有。
- 新建项目/迭代/排期仍是页面内的表单卡片，不是 modal；实际交互需要 modal 的关闭/Escape/焦点陷阱/长表单滚动。已有 release/clear/waiver modal，可以复用同一套 shell。
- 版本更新卡已有「查看发布说明」和 release modal，保留。

### 5. 证据/审批交互

- 交付报告「查看最新版本」和证据「打开/下载」按钮没有行为；需要明确打开的是报告版本面板/证据文件列表，而不是只改检视器。
- 「通过/驳回」按钮没有确认/原因；当前实现是 approve 确认，设计至少要有二次确认，驳回建议必填理由。
- 证据包写 `state: verified`，现有模型是 `state: ready / finalizing / expired / integrity-failed` + `integrity: verified / failed`；建议显示 `state: ready · integrity: verified`。
- 证据包只有单个文件，没有 items 列表；现有 bundle 是多 item 的。可以显示 item 数 + 展开列表。

### 6. 移动端证据/审批

- 移动端证据只列 2/5 checks（见 P0）。
- 移动端审批按钮直接出现，没有先看到完整 checks；应保证 5 项都在上面，或折叠时明确「2 项阻断」。
- 移动端检视器 sheet 已有，保留。

### 7. 设计系统/交接

- `components/` 目录仍然不存在，但设计系统引用了 `@components/*.html`；实现者只能从页面反推组件。
- 字体仍是 Google Fonts 的 Red Hat/Instrument Sans（中文回退），且仍使用 Tailwind CDN；本地/离线场景需要系统字体或本地 woff2 + 手写 CSS。
- 英文支持没有落到页面（见 P0 第 3 点）。
- `data-stitch-vh`、`预览模态弹窗`、`正常目录` 这类设计工具/原型控件需要在交付前去掉。
