# dsh-qa 界面评审

评审对象：`public/index.html` 与 `public/style.css`
评审日期：2026-08-21
评审方式：静态代码检查 + 本地浏览器渲染检查

## 结论

当前界面已经具备可信的 QA 工作台基础：导航清楚、颜色语义稳定，“今日待办”也能帮助用户快速发现风险。

最大问题不是视觉质量不足，而是首屏同时展示了太多同等重要的信息。用户进入后仍需要判断：应该先看指标、待办、日程、项目、AI 辅助，还是最近动态。

首要方向应是：把“现在需要我做什么”变成首屏唯一明确的行动入口。

## 优先级问题

### P1：首屏存在过多竞争性重点

指标卡、待办、日历、项目、AI 控制和最近动态具有相近的视觉权重。

影响：用户需要先决定“看哪里”，才能开始工作。

建议：

- 将逾期、待审批、阻塞事项合并为一个“需要你处理”队列。
- 将指标卡降级为辅助信息。
- 将最近动态和 AI 状态下移或放入次级视图。

### P1：辅助文字过小、对比度偏弱

大量标签、元数据和说明使用约 8.5–10.5px 字号，并使用较浅的灰色。

影响：中文内容在密集界面中难以快速扫描，也会削弱“证据”和“装饰性信息”的区别。

建议：

- 普通 UI 文字尽量不低于 11px。
- 9–10px 只用于时间戳和徽标。
- 加深 `--faint`，优先使用字重和间距建立层级。

### P1：助手工作区的上下文成本较高

项目栏、聊天区、模型/测试模式提示、输入区和项目雷达同时表达“当前上下文”。

影响：首次使用者不容易判断哪个面板拥有下一步动作。

建议：

- 中央聊天区只保留一个明确的任务标题和主操作。
- 较窄屏幕默认收起项目雷达。
- 将模型与测试模式合并成一个紧凑状态入口。
- 让项目上下文只在一个主要位置作为权威来源。

### P2：风险状态没有稳定地指向解决动作

“逾期 15 天”“待审批”“建议处理”能说明问题，却没有说明最快的安全处理路径。

建议把它们改成动作导向的文案，例如：

- “补齐需求”
- “打开评审”
- “提交审批”
- “查看阻塞原因”

## 用户角色风险

### 熟练用户

搜索和 `⌘ K` 是优点，但首页仍需要扫描多个模块才能进入主要动作；助手工作区的多面板也会降低操作速度。

### 首次使用者

“DSH 测试模式”“全流程辅助”“项目雷达”“门禁”等术语不够自解释。新建项目按钮需要更明确地说明点击后会发生什么。

### QA 负责人

逾期和审批状态可见，但负责人、截止日期影响和安全处理路径没有始终明确。用户仍可能需要打开详情页才能判断发布是否被阻塞。

## 做得好的地方

- 顶部搜索、主导航、最近项目形成了清楚的工作入口。
- 蓝、红、琥珀、青绿色的语义相对稳定，没有过度使用高饱和色。
- “今日待办”把紧急程度、项目上下文和时间信息放在一起，是当前最有效的模块。

## 建议实施顺序

1. 先收敛首页，把“需要你处理”设为主任务入口。
2. 再调整字号、灰度和信息层级。
3. 然后简化助手工作区的上下文表达。
4. 最后处理侧边强调线、布局动画、焦点状态和减少动效。

## 需要确认的问题

- 首页主要服务于 QA 日常分诊，还是主要用于进入 DSH 测试助手？
- 本轮只处理前三项 P1 问题，还是连同 P2 一起完成？
- 项目雷达需要常驻显示，还是更适合作为按需打开的辅助面板？
