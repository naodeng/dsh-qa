## 二、仍然是 P0 的 7 个问题

### 1. 首页对话输入框在 900px 高度下仍然在视口外

v3 用了固定 `lg:h-[1024px]` 设计画布，而不是 `100vh`。实测 1440×900：

```
copilot-input top = 978px
viewport height   = 900px
```

也就是说，在 900px 高的笔记本上，输入框仍然看不到。需要在实现规范里改成 `h-screen` / `h-[calc(100vh-顶栏)]`，并补一张 900/768 高度的稿验证。

### 2. 新建排期表单缺「事项名称」字段

v3 的排期表单有：关联项目、日期、类型、备注/依据；**没有 title**。现有 `POST /api/projects/:id/schedule` 要求 `title` 必填，缺了它无法创建。

需要补：

- 事项名称（必填）
- 日程/里程碑切换已有
- 里程碑的 `kind`（release/review/freeze/other）已有
- 备注/依据已有

### 3. 门禁语义还有三处错

1. **`stale-evidence` 被解释成「超过 7 天有效期」**。现有检查是「测试运行/证据与当前输入（provenance）不一致」，不是时效。证据过期是 retention/`expired` 状态，不是 stale-evidence。设计里的 `ev_99a1b2 已超 7 天有效期 (stale-evidence)` 需要改。
2. **`verified-evidence` 显示 `passed · block`**。`block` 是规则严重度，不是结果；放在「结果 / 级别」一列里会让人误读。建议拆成「结果」和「级别」两列，或只在 failed 时显示严重度。
3. **`critical-risk` 的说明与缺陷页不一致**：缺陷页 `risk_01` 是「并发幂等压测证据已超 7 天未刷新」，门禁页却说「未闭环的高危并发风险」，同一风险两个说法。需要统一。

另外：设计写「所有 block 与 warn 检查项均为 passed（或已合法豁免）→ PASS」，但当前 `applyGateExceptions` 对 waived warn 仍然会得到 WARN（`hasWarn` 只看 status=failed）。要么改后端，要么把 PASS 条件写成「所有 block 检查 passed，且 warn 检查 passed（waived 仍为 WARN）」。

### 4. Host 执行仍然是虚构的 `127.0.0.1:4318`

工作区「执行与 Host 配置」和状态页都写了：

```
Host: http://127.0.0.1:4318 (已连接)
ECONNREFUSED 127.0.0.1:4318
```

现有模型没有固定的本地 Host 端口。Host 执行是通过 DSH host adapters（browser-use / computer-use / mcp）和 execution profile 的 provider/capabilities/targetPolicy 完成的；本地运行是 controlled-local。设计需要改成：

- 执行配置：选择 profile / provider / capability / target / timeout
- 预览：显示 target、profile、artifact policy
- 确认：确认后记录 run/host execution
- 失败：显示 adapter unavailable / provider_error，而不是固定 4318 端口

### 5. 工作区还没覆盖质量任务的全部子实体

v3 的质量任务 tab 有：任务卡、决策/计划、Host 配置、3 步执行、运行记录。仍缺：

- 测试计划（testPlans）与用例集
- 来源（sources）与采集摘要
- 决策明细（decisions）
- 故障分析（failureAnalyses）与「确认并创建缺陷」
- 回归集（regressionSets）与计算/排除
- 执行配置（executionProfiles）与 Host 配置（hostExecutions）列表
- 项目级运行/项目记录
- 质量风险的评估/处置（assessmentStatus/dispositionStatus）与决策
- 缺陷状态流转（当前只有筛选，没有变更）
- 待审批门禁的通过/驳回动作
- 门禁例外表单（actor/reason/expiresAt；当前 `applyWaiver` 一键改 badge）
- 证据包的 state/integrity/items、下载/打开、清理任务
- 报告的查看最新版本/版本列表（当前只有 docType 行）
- 项目阶段变更的键盘/非拖拽入口（当前只能拖看板；元数据里没有阶段选择）

## 四、门禁语义最终表（建议直接贴进设计规范）

| 检查项 | 状态 | 严重度 | 可豁免 | 说明 |
| --- | --- | --- | --- | --- |
| `stale-evidence` | passed / failed | block | 否 | 运行或证据的 provenance 与当前输入不一致，不是「7 天过期」 |
| `verified-evidence` | passed / failed | block | 否 | 存在通过完整性校验且与运行匹配的证据 |
| `critical-test-result` | passed / failed | block | 否 | 存在受控且通过的关键测试运行 |
| `critical-risk` | passed / failed | block | 否 | 没有未处置的 critical 风险 |
| `medium-coverage` | passed / failed | warn | 是 | 中高风险范围有覆盖；可记录 actor/reason/expiresAt 例外 |

总体 verdict：

- 任一 `severity=block` 的 check `failed` 且未豁免 → **BLOCK**
- 否则任一 check `failed` → **WARN**
- 否则 → **PASS**

注意：当前 `applyGateExceptions` 对 waived warn 仍返回 WARN；如果产品希望「合法豁免后 PASS」，需要改后端，不能只改设计文案。
