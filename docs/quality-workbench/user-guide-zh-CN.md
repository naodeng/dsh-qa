## 1. 产品定位与运行模式

dsh-qa 是 DeepSeek Harness（简称 DSH）的本地 QA 工作台。它将项目、需求、测试用例、缺陷、执行记录、证据和交付结论集中在同一项目空间中。项目数据保存在运行 dsh-qa 的本机上；使用 DSH 插件时，对话、模型、技能和命令由 DSH 提供。

| 模式 | 适合场景 | 可以使用 | 不提供 |
| --- | --- | --- | --- |
| DSH 插件模式（推荐） | 日常测试协作 | 工作台、项目数据、DSH 测试对话、模型、技能、命令及宿主执行接入 | 多人或云端同步 |
| 独立运行模式 | 体验工作台、维护本地项目材料 | 测试首页、项目、看板、日历和项目资料 | DSH 对话、模型切换、技能和命令 |

首次使用建议选择 DSH 插件模式。仅想先看页面时，可以直接启动独立模式。

## 2. 安装前准备

- DSH 插件和独立模式都需要 Node.js 18 或更新版本。
- 使用 DSH 插件模式前，需要先安装并能正常启动 DeepSeek Harness。
- DSH Web 模式应使用与启动 DSH 相同的方式管理插件：通过 `npx` 启动就用 `npx` 管理；从 Harness 源码启动就用 `pnpm dsh` 管理。
- 官方 macOS 客户端由客户端自身管理 `desktop` profile，不能用 CLI 的 `--profile desktop` 命令安装插件。

检查 Node.js：

```bash
node --version
```

## 3. 安装与启动

### 3.1 DSH Web：通过 npx 启动

```bash
# 安装插件
npx --yes @deepseek-ai/dsh plugin --profile web add dsh-qa

# 启动或重启 DSH Web，让新插件加载
npx --yes @deepseek-ai/dsh web
```

更新插件：

```bash
npx --yes @deepseek-ai/dsh plugin --profile web update dsh-qa
npx --yes @deepseek-ai/dsh web
```

重启后，在 DSH 侧边栏打开「质量工作台」。主插件包同时包含 `qa`（测试模式）和 `quality-control`（研发质量控制模式）两个 preset。

### 3.2 DSH Web：从 Harness 源码仓库启动

在已完成 Harness 依赖安装和构建的仓库根目录运行：

```bash
# 安装插件
pnpm dsh plugin --profile web add dsh-qa

# 启动或重启 DSH Web
pnpm dsh web
```

更新插件时，将 `add` 改为 `update`：

```bash
pnpm dsh plugin --profile web update dsh-qa
pnpm dsh web
```

需要从本地仓库或指定 GitHub 仓库安装时，将 `add dsh-qa` 替换为 `add link:/本地仓库路径` 或 `add github:naodeng/dsh-qa`。

### 3.3 官方 macOS DSH 客户端

1. 在 DSH 客户端的 **Plugins** 页面选择添加插件或 Git 仓库。
2. 输入 `https://github.com/naodeng/dsh-qa` 并安装。
3. 安装或更新后按 `⌘Q` 完全退出 DSH，再重新打开。
4. 从侧边栏进入「质量工作台 / QA Workbench」。

客户端的 `desktop` profile 由客户端管理，不要用 `dsh plugin --profile desktop` 安装或更新。

### 3.4 npm 独立运行

```bash
npm install -g dsh-qa
qabench
```

默认打开 `http://127.0.0.1:8899`。停止服务时，在启动终端按 `Ctrl+C`。更新后需重新启动：

```bash
npm update -g dsh-qa
qabench
```

独立模式不需要 DSH 登录、模型 API Key 或生产依赖；但它也不会提供 DSH 对话、模型、技能和命令。

### 3.5 从 GitHub 克隆体验或开发

```bash
git clone https://github.com/naodeng/dsh-qa.git
cd dsh-qa
npm start
```

服务默认使用 `http://127.0.0.1:8899`。首次启动会生成示例项目和迭代，你可以先通过首页、看板和日历熟悉界面。

## 4. 第一次使用

### 4.1 新建测试项目或迭代

在左侧项目栏点击「＋」，选择对象类型并填写项目名称。建议一并填写项目编号、被测产品、负责人和测试范围摘要。勾选「创建本地项目文件夹」后，工作台会生成需求、计划、用例、数据与脚本、执行、缺陷、报告和归档等目录。

如果要在测试项目中管理一个短周期，可以创建「迭代」并关联父项目；如果需要单独维护测试对话和工作区，则创建「测试项目」。

### 4.2 认识主要页面

- **测试首页**：查看待处理事项、在办项目、近期日程、逾期里程碑、待审批门禁和最近动态。点击项目卡片可进入项目详情。
- **DSH 测试对话**：仅在插件模式下可用。每个项目都有独立的 DSH 会话，会话自动使用 `qa` 测试模式。
- **项目看板**：通过六个阶段跟踪项目：需求分析、用例设计、用例评审、执行中、缺陷回归、已发布。可拖动卡片调整阶段；发布仍需负责人确认。
- **日历排期**：查看里程碑和日程，支持按年、月、日跳转，也可在选定日期新增日程。
- **QA Skill 安装**：在 DSH 插件模式下浏览、搜索并安装配套 QA Skill。
- **项目详情**：集中维护项目概览、质量任务、需求、用例、缺陷、里程碑、报告、知识、纪要和门禁。

### 4.3 检查 DSH 模型与对话

插件模式下，工作台不单独保存模型或 API Key。请先在 DSH 设置中配置模型和凭据，再从「DSH 测试对话」顶部选择可用模型。首次进入项目时，工作台会为该项目绑定 DSH 测试会话；项目文件夹会作为会话工作目录。

独立运行地址（默认 `127.0.0.1:8899`）只打开工作台页面。要使用 DSH 会话和技能，请从 DSH 侧边栏打开插件入口。

## 5. 日常工作流

### 5.1 从需求整理到测试用例

在项目对话中给出需求、验收标准和已确认的代码或文档上下文。可以这样提出任务：

> 请先整理这项需求中的已确认事实、待澄清点和风险，再按正向、异常和边界场景设计可执行且预期结果明确的测试用例。将需求与用例关联，先给我检查结果，再登记到当前项目。

对话工具可以把需求、用例和追踪关系登记到当前项目。完成后，到项目详情的「需求」和「用例」分区检查覆盖关系，再将用例状态从「草稿」更新为「已评审」或「已执行」。

### 5.2 登记和跟踪缺陷

描述缺陷时尽量提供环境或版本、复现步骤、预期结果、实际结果、复现频率和业务影响。可以要求 DSH 只登记观察到的事实，并将不确定的原因单独标注为猜测。缺陷状态可在项目详情中更新为待处理、修复中、待验证或已关闭。

### 5.3 安排里程碑和日程

在日历中选择日期并新增日程，或在项目对话中要求登记评审、冻结和发布日期。项目详情中的里程碑、会议和工作日程会同步显示在日历中；首页也会提示临期和逾期节点。

### 5.4 请求评审并由负责人审批

可以在对话中要求提交需求评审、策略评审、用例评审、报告评审、发布或结项门禁。申请会出现在项目「门禁」分区和首页待处理事项中。负责人检查材料后手动通过或驳回；AI 不能代替负责人审批，也不能自行批准发布。

### 5.5 生成报告并保存

提供测试范围、执行事实、失败和未执行事项后，可以要求 DSH 起草测试计划、测试报告、缺陷报告、发布说明或测试总结。检查报告中的执行状态和证据是否准确，再保存为项目报告草稿。不要把计划、代码阅读或构建成功写成已执行测试。

## 6. 功能说明

### 项目、迭代和工作区

- 项目与迭代均可独立查看和维护；迭代可以关联父项目。
- 项目概览记录编号、产品、负责人、摘要、阶段、成员和 DSH 协作策略。
- 可自动创建本地项目目录，便于整理测试材料。
- 删除项目记录不会自动删除关联文件夹；删除前请确认选中的项目记录无误。

### 测试首页、看板和日历

- 首页把项目状态、待处理事项、日程和最近材料集中展示。
- 看板用于跟踪项目阶段，状态会实时更新到同一台机器上打开的其他工作台窗口。
- 日历统一展示项目日程和里程碑，可按日期筛选、跳转和新增。

### 需求、用例、缺陷和知识材料

- 需求可记录功能范围、非功能要求、风险点和验收标准。
- 用例可记录类型、优先级、前置条件、步骤、预期、需求追踪和风险标签。
- 缺陷可记录严重级别、环境、复现步骤、预期与实际、频率和影响。
- 项目还可保存测试知识、会议纪要和多个版本的报告草稿。

### DSH 协作与 QA Skill

- DSH 对话、模型、命令、技能及权限策略均由 Harness 提供。
- 每个项目使用自己的 DSH 会话；通过 AI 登记的资料会显示在项目详情和最近动态中。
- 「QA Skill 安装」页面从本地 `awesome-qa-skills` 仓库读取目录，默认位置为 `~/awsomeCode/awesome-qa-skills`。仓库放在其他位置时，在启动工作台前设置 `QA_SKILLS_ROOT` 指向仓库根目录。
- 在「QA Skill 安装」页面搜索所需技能并安装。技能会复制到 DSH 技能目录（默认 `~/.dsh/skills/`）；安装后重启 DSH，再在新会话中使用。也可在对话框输入 `/` 搜索已安装的技能或命令。
- DSH 会话可以协助分析和登记，但项目阶段、风险接受、缺陷确认、门禁审批和发布等决定仍由负责人把关。

### 界面偏好

在设置中切换中文或 English，以及明亮、暗黑或跟随系统的外观。主导航、项目栏和项目雷达都可以收起，也可以拖动分隔线调整宽度；双击分隔线可恢复默认宽度。

## 7. 进阶：质量任务、执行与门禁

如果你需要为某项变更或某个版本留存来源、验收标准、风险、测试范围、运行结果和证据，可以使用这一部分的功能。入口位于项目详情的「质量任务」分区。

### 7.1 创建质量任务并补全分析

点击「新建质量任务」并填写任务名称，例如「支付回调变更验收」。当前创建窗口只录入名称；后续的来源快照、验收标准、风险和测试范围，需要由 DSH 质量分析流程或受支持的服务端 API 补全。分析结果应对应已采集的来源快照和当前任务版本。

分析前，请说明要检查的需求、工作区文件或 Git 修订，并明确本次验收范围。检查并确认分析结果后，由负责人决定风险是确认、缓解、关闭还是接受。AI 给出的风险建议不等于人工风险决定。

### 7.2 执行配置与受控运行

项目详情支持创建本地执行配置，可选择 Node Test 或 Playwright 作为执行器。目标应填写项目工作区中具体测试文件的路径，不使用通配符。只有测试计划属于当前版本且已评审，服务端质量流程才允许生成运行预览并开始测试。

工作台也支持创建 Host 执行配置，提供 `browser-use`、`computer-use` 和 `mcp` 类型。配置时可限制可访问来源或 MCP 工具，并选择日志、截图和 trace 等材料。运行前先查看预览并明确确认启动；运行中可以取消，结束后可以重试。

Host 执行取决于当前 DSH 宿主是否提供对应的 provider/adapter。适配器不可用时，运行会记为未执行。配置保存成功或请求已发送，都不能证明测试已经运行。

> 当前页面提供执行配置和 Host 执行入口；创建测试计划、评审版本和生成本地运行预览也有服务端 API 契约，但部分步骤尚未提供图形界面入口。

### 7.3 检查证据、失败和回归

- 运行结束后可形成证据包；检查证据包的状态和完整性，只有已验证的证据才可作为交付依据。
- 可为受控运行中的失败记录故障分析。将分析升级为缺陷前，负责人需要填写确认人信息并确认操作。
- 可建立确定性回归集，并记录排除用例的操作者和理由。
- 可以比较同一测试计划的两次已结束运行，查看用例状态变化和修复效果。

### 7.4 评估质量门禁

在质量任务分区选择「评估质量门禁」后，工作台按来源、运行、验证过的证据、关键测试结果和风险状态计算交付结论：

- `PASS`：按当前计算规则，阻断项均已满足。
- `WARN`：存在需要负责人查看的警告或未满足的非阻断项。
- `BLOCK`：存在阻断交付的问题；先查看交付报告中的检查项并补齐运行、证据或风险处理。

门禁结论由工作台根据当前数据计算，不等于负责人已批准发布。只有规则允许的警告检查项可以登记为例外，登记时必须填写责任人、原因和到期时间。例外不会将 `BLOCK` 改为 `PASS`。

## 8. 数据位置与协作边界

- DSH 插件模式的项目记录和工作台数据默认保存在 `~/.dsh/dsh-qa/`；独立运行模式默认保存在仓库或全局安装位置对应的 `data/` 目录。
- DSH 对话记录由 DSH 保存，与工作台的 JSON 数据分开。
- 项目数据保存在本地，看板实时更新只在同一台机器上的工作台窗口间生效；不会自动同步给其他成员，也不会监听 GitHub 远端变化、自动拉取代码或同步项目记录。
- 质量任务可以根据受支持的来源生成本地快照；dsh-qa 不会与 Git、Issue、WPS 或禅道同步项目数据。
- 请按组织的数据管理要求备份本地项目数据和项目工作区文件。

独立运行时可用环境变量调整默认数据目录或监听端口，例如：

```bash
QA_DATA_DIR=/path/to/qa-data QA_PORT=8900 npm start
```

## 9. 常见问题

**侧边栏没有「质量工作台」入口**

确认插件已安装到正在使用的 DSH profile，并完全重启 DSH。官方 macOS 客户端需 `⌘Q` 退出后重新打开。

**看不到 DSH 对话、模型、技能或命令**

确认是从 DSH 侧边栏打开插件，而不是直接访问 `127.0.0.1:8899` 的独立页面。再检查 DSH 中的模型、凭据和技能配置。

**模型鉴权失败**

在 DSH 设置中检查服务商、模型和凭据。dsh-qa 不单独保存 API Key。

**质量门禁显示 `BLOCK`**

打开项目的「质量任务」分区查看交付报告和阻断检查项。先完成受控运行、补充有效证据或作出风险决定，再重新评估。

**本地测试没有运行或没有证据包**

检查测试计划是否为当前版本且已评审、执行配置指向的测试文件是否位于项目工作区内，以及所需的执行器或 Host adapter 是否可用。运行状态不是 `passed` 时，不应表述为测试通过。

**端口 8899 已被占用**

检查是否已有工作台进程在运行；独立模式可设置 `QA_PORT` 使用其他端口。
