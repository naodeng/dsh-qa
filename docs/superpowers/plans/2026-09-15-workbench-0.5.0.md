# DSH QA Workbench 0.5.0 Implementation Plan（Native Harness Panel Integration）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 Harness 官方 `sidebar.panellist` 和 root-scoped `main` keyed slot 接入 dsh-qa，删除对宿主 DOM implementation detail 的依赖，同时保留现有 Workbench iframe。

**Architecture:** `lib/client.js` 只保留一个官方 Panel 注册适配层和 iframe lifecycle；sidebar entry 的 `id` 与 main keyed slot 的 key 都是 `dsh-qa`。Panel selection 由 Harness 管理，不再使用 querySelector、MutationObserver 或自建互斥事件。

**Tech Stack:** Node.js ESM、Harness `dsh-v0.1.6-alpha.1` Panel/Slot API、原生浏览器 JavaScript、Playwright、Node `node:test`。

**Spec:** `docs/quality-workbench/2026-09-15-requirements.md` §4.2；`docs/quality-workbench/2026-09-15-solution-design.md` §3.2；`docs/quality-workbench/2026-09-15-technical-design.md` §4。

**Depends on:** 0.4.1 的兼容矩阵已完成适用项，且目标 Harness Panel/Slot contract 已由当前 alpha 版本锁定。

## Global Constraints

- 不重写 `public/` Workbench，不在 dsh-qa 包中新增或打包 React 生产依赖；Panel shell 可使用 Harness 提供的 React runtime，不复制 Project/quality 数据模型。
- 保留 `/api/dsh-qa/workbench/`、iframe sandbox、popout、返回 DSH 消息和独立模式。
- 不保留 selector fallback；官方 Panel API 失败时显示可解释错误并停止挂载，不偷偷回退 DOM 注入。
- 不保留 `data-dsh-qa-active`、`data-dsh-law-active` 等跨插件状态清理和 `dsh-panel-activate` 协议。
- Panel 选择、iframe mount/unmount、listener cleanup 和重复加载必须有真实宿主证据。
