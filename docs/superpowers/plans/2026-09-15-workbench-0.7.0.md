# DSH QA Workbench 0.7.0 Implementation Plan（AI Quality Intelligence）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从 Evidence、Failure Analysis、RegressionSet、QualityGate 和 provenance 事实生成可解释的 Quality Insight、Auto Review 和下一步建议，不让 AI 绕过确定性门禁或人工审批。

**Architecture:** 先运行确定性 insight rules，再可选调用 DSH Auto Review。AI 输出是经过 schema 校验的候选建议，带 target/reason/evidenceRefs/confidence/nextAction；写入 Insight、promote 缺陷或修改回归集/Gate 都需要领域 API、revision 和人工确认。

**Tech Stack:** Node.js ESM、现有质量领域服务、JSON store、原生 HTTP/SSE、Node `node:test`、Playwright、DSH host Auto Review（opt-in）。

**Spec:** `docs/quality-workbench/2026-09-15-requirements.md` §4.4；`docs/quality-workbench/2026-09-15-solution-design.md` §3.4；`docs/quality-workbench/2026-09-15-technical-design.md` §6。

**Depends on:** 0.6 的 TestRun provenance 和 EvidenceBundle 产物已经可验证。

## Global Constraints

- Insight 是事实的可解释投影，不复制 Requirement、TestCase、Evidence 或 Gate 主模型。
- 确定性规则优先；模型只能读取结构化快照，不能直接写 JSON store 或调用任意工具。
- 每条建议必须带证据引用；引用不存在、过期或完整性失败时显示缺口，不补齐推测。
- AI recommendation、failure category、regression recommendation 和 gate recommendation 都不是事实或 verdict。
- `PASS/WARN/BLOCK` 仍由现有确定性 Gate 计算；AI 不能把 `BLOCK` 改为 `PASS`。
- standalone 模式可运行确定性规则；没有 DSH 时 Auto Review 明确降级为 unavailable。

**Files:**

**Interfaces:**

- [ ] **Step 1: Write failing rule tests**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { analyzeQualityFacts } from '../../server/quality/insights/engine.js';

test('finds evidence and regression gaps from saved facts', () => {
  const first = analyzeQualityFacts({
    projectId: 'project_1',
    requirements: [{ id: 'req_1', acceptanceCriteria: [] }],
    testcases: [{ id: 'tc_1', trace: ['req_1'] }],
    risks: [{ id: 'risk_1', severity: 'critical', status: 'open' }],
    evidenceBundles: [],
    regressionSets: [],
    gates: [],
  });
  const second = analyzeQualityFacts({
    projectId: 'project_1',
    requirements: [{ id: 'req_1', acceptanceCriteria: [] }],
    testcases: [{ id: 'tc_1', trace: ['req_1'] }],
    risks: [{ id: 'risk_1', severity: 'critical', status: 'open' }],
    evidenceBundles: [],
    regressionSets: [],
    gates: [],
  });
  assert.ok(first.insights.some((item) => item.kind === 'evidence_gap'));
  assert.equal(first.inputDigest, second.inputDigest);
});

test('does not call a missing evidence reference covered', () => {
  const { insights } = analyzeQualityFacts({ requirements: [], testcases: [], evidenceBundles: [], gates: [{ id: 'gate_1', checks: [{ evidenceRefs: ['missing'] }] }] });
  assert.ok(insights.some((item) => item.evidenceRefs.includes('missing')));
});
```

- [ ] **Step 2: Run the focused test**

Run: `node --test test/unit/quality-insights.test.js`

Expected: FAIL because the insight modules do not exist.

- [ ] **Step 3: Implement stable rules and digesting**

Implement `requirement_gap`, `coverage_gap`, `evidence_gap`, `regression_gap`, `automation_gap` and `release_risk` as pure rules over a normalized snapshot. Sort IDs before hashing. Each insight includes `id`, `kind`, `target`, `reason`, `evidenceRefs`, `severity`, `status` and `inputDigest`; repeated analysis of the same facts is deterministic.

- [ ] **Step 4: Add audited resolve/ignore mutations**

Require `expectedRevision`, non-empty actor label and a reason for ignore. Reject stale revisions with `409`; do not delete the original insight or change Gate facts.

- [ ] **Step 5: Run and commit**

Run: `node --test test/unit/quality-insights.test.js test/unit/quality-gate.test.js`

Expected: insight and existing Gate tests PASS. Commit `feat: add deterministic quality insights`.

### Task 2: Add schema-validated Auto Review candidates

**Files:**
- Create: `server/quality/insights/auto-review.js`
- Create: `test/unit/auto-review.test.js`
- Modify: `server/routes.js`
- Modify: `test/unit/http-api.test.js`

**Interfaces:**
- `validateReviewCandidate(candidate, snapshot) → normalizedCandidate`
- `reviewQualitySnapshot(snapshot, reviewer) → { recommendations, reviewer, inputDigest }`

- [ ] **Step 1: Test accepted and rejected candidates**

Accept a candidate with `type`, `target`, `reason`, existing `evidenceRefs`, `confidence` between 0 and 1 and a bounded `nextAction`. Reject unknown fields, missing references, oversized text, invalid confidence and any candidate that contains `verdict: 'PASS'` or a direct store mutation.

- [ ] **Step 2: Implement a reviewer boundary**

The default local reviewer returns `unavailable`; the opt-in DSH reviewer receives only the structured snapshot and returns untrusted data to the validator. Do not make a model call in standard unit/API tests.

- [ ] **Step 3: Expose read-only candidate APIs**

Add project-nested preview/review routes that return candidates without applying changes. Any application route must delegate to existing defect, regression, Gate or approval APIs and require their own revisions/confirmation.

- [ ] **Step 4: Run focused API tests**

Run: `node --test test/unit/auto-review.test.js test/unit/http-api.test.js`

Expected: candidate schema, missing evidence and no-direct-write cases PASS.

- [ ] **Step 5: Commit**

```sh
git add server/quality/insights/auto-review.js server/routes.js test/unit/auto-review.test.js test/unit/http-api.test.js
git commit -m "feat: validate AI quality review candidates"
```

## Out of scope for 0.7.0

- Quality Obligation generation from arbitrary AST or complete Quality Evidence Graph.
- Autonomous Agent Loop, multi-agent orchestration and external policy engine.
- Direct Gate mutation, automatic defect filing or automatic production release.
