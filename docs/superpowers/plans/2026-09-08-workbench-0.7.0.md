# DSH QA Workbench 0.7.0 Implementation Plan（对话工作台）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 DSH 测试对话视图成为 QA 的高效操作面——有下一步建议、材料回填、常用快捷条，会话绑定状态清晰。

**Architecture:** 前端纯函数 `buildNextSteps` + 快捷条模板；材料流点击写入输入框；会话绑定只读展示项目 `dshSessionId` 与宿主能力；独立模式仅开放非对话类建议。

**Tech Stack:** 原生 `public/`、`node:test`（纯函数）、Playwright。

**Spec:** technical-design §4；需求 §5.2。
**Depends on:** 0.6 深链约定（`href.view` / project tab）；可并行修小冲突但应先合并 0.6。

## Global Constraints

- 建议默认不自动调用写 API；插入 prompt 或打开确认 UI。
- 不伪造 DSH session；独立模式诚实降级。
- 不新增生产依赖。

### Task 1: `buildNextSteps` pure function

**Files:**
- Create: `public/next-steps.js`（若仓库坚持单文件，则把纯函数放 `public/app.js` 顶部并在 node 侧用复制测试——**优先独立 ESM 文件**，用 Playwright/浏览器或把逻辑放 `server/` 不可取；推荐 `public/next-steps.js` + 在 `test/unit/next-steps.test.js` 用 Node 直接 import，因项目为 ESM。）
- Create: `test/unit/next-steps.test.js`

**Interfaces:** 见 technical-design §4.1。

- [ ] **Step 1: Failing tests**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { buildNextSteps } from '../../public/next-steps.js';

test('standalone mode never returns insert_prompt', () => {
  const steps = buildNextSteps({
    mode: 'standalone',
    project: { id: 'p1', status: 'execute', dshSessionId: null },
    queueItems: [],
    qualityTasks: [],
  });
  assert.equal(steps.every((s) => s.action !== 'insert_prompt'), true);
});

test('suggests gate tab when approval pending in queue', () => {
  const steps = buildNextSteps({
    mode: 'dsh',
    project: { id: 'p1', status: 'review', dshSessionId: 'sess_1' },
    queueItems: [{ kind: 'gate_pending', projectId: 'p1', entityId: 'g1' }],
    qualityTasks: [],
  });
  assert.ok(steps.some((s) => s.action === 'open_tab' && s.payload.tab === 'gates'));
});
```
