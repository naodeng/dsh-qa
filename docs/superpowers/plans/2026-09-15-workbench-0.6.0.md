# DSH QA Workbench 0.6.0 Implementation Plan（Native QA Execution）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把现有 Execution Profile 接到 Harness Browser Use、Computer Use 或 MCP 的受控执行能力，并把每次结果可靠地映射为 TestRun 和 EvidenceBundle。

**Architecture:** 新增 HostExecution adapter 边界，不让模型文本直接调用工具；Profile 决定 provider、capability、权限和 artifact policy。Host result 先进入现有 TestRun provenance，再进入 staging/finalize/verify EvidenceBundle，质量门禁继续只读取可信事实。

**Tech Stack:** Node.js ESM、现有 JSON store/HTTP/SSE、Harness host capabilities、Node `node:test`、Playwright。

**Spec:** `docs/quality-workbench/2026-09-15-requirements.md` §4.3；`docs/quality-workbench/2026-09-15-technical-design.md` §5。

**Depends on:** 0.4.0 的 TestRun/Evidence/Gate contract 和 0.5.0 的 Panel lifecycle 已验证。

## Global Constraints

- Host execution 只能从已保存、已评审的 Execution Profile 派生。
- provider/capability、target、timeout、artifact policy 和 workspace 权限都使用白名单。
- Fake adapter 只用于 standalone unit/API/E2E，不伪造真实 Harness host evidence。
- `imported-summary`、未 finalize 的 artifact 或无 provenance 的 host result 不能满足 PASS。
- 取消、超时、断线、重试、部分 artifact 和 provider error 都要保存可审计状态。
- 不增加生产 npm 依赖，不把 HostExecution contract 扩散成第二套 TestRun 模型。

**Interfaces:**

- [ ] **Step 1: Write failing contract tests**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { validateHostExecutionRequest, mapHostExecutionResult } from '../../server/quality/harness-execution.js';

test('accepts only profile capabilities and returns a normalized request', () => {
  const project = {
    qualityTasks: [{ id: 'qt_1', revision: 3, executionProfiles: [{ id: 'profile_1', version: 2, providers: ['browser-use'], capabilities: ['navigate'] }] }],
  };
  const request = validateHostExecutionRequest(project, 'qt_1', {
    profileId: 'profile_1', provider: 'browser-use', capability: 'navigate', target: 'https://example.test', timeoutMs: 30_000, expectedRevision: 3,
  });
  assert.equal(request.provider, 'browser-use');
  assert.equal(request.profileVersion, 2);
});

test('maps a host result to provenance without creating a PASS verdict', () => {
  const patch = mapHostExecutionResult({}, { id: 'host_1', provider: 'browser-use', profileVersion: 2 }, { status: 'passed', artifacts: [{ relativePath: 'trace.zip', type: 'trace' }] });
  assert.equal(patch.status, 'passed');
  assert.equal(patch.provenance.hostExecutionId, 'host_1');
  assert.equal('verdict' in patch, false);
});
```

## Out of scope for 0.6.0

- Automatic test planning or AI failure interpretation; that is 0.7.0.
- Arbitrary shell execution, unrestricted MCP servers, production credentials or host mounts.
- Multi-agent orchestration and autonomous release decisions.
