# DSH QA Workbench 0.6.0 Implementation Plan（Native QA Execution & Action Desk）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把现有 Execution Profile 接到 Harness Browser Use、Computer Use 或 MCP 的受控执行能力，把每次结果可靠地映射为 TestRun/EvidenceBundle，并让首页 Action Desk 暴露需要处理的执行和质量状态。

**Architecture:** 新增 HostExecution adapter 边界，不让模型文本直接调用工具；Profile 决定 provider、capability、权限和 artifact policy。Host result 先进入现有 TestRun provenance，再进入 staging/finalize/verify EvidenceBundle，质量门禁继续只读取可信事实。Action Queue 只读聚合这些事实，首页以它作为“需要你处理”的唯一数据源，旧 `reminders` 由兼容投影提供。

**Tech Stack:** Node.js ESM、现有 JSON store/HTTP/SSE、Harness host capabilities、Node `node:test`、Playwright。

**Spec:** `docs/superpowers/specs/2026-09-23-workbench-0.6-native-execution-action-desk-design.md`；`docs/quality-workbench/2026-09-15-requirements.md` §4.3；`docs/quality-workbench/2026-09-15-technical-design.md` §5。

**Depends on:** 0.4.0 的 TestRun/Evidence/Gate contract 和 0.5.0 的 Panel lifecycle 已验证。

## Global Constraints

- Host execution 只能从已保存、已登记且当前启用的 Execution Profile 派生，并在每次执行前经过预览确认。
- provider/capability、target、timeout、artifact policy 和 workspace 权限都使用白名单。
- Fake adapter 只用于 standalone unit/API/E2E，不伪造真实 Harness host evidence。
- `imported-summary`、未 finalize 的 artifact 或无 provenance 的 host result 不能满足 PASS。
- HostExecution → TestRun → EvidenceBundle → Gate 使用现有事实模型：Host TestRun 为 `mode: 'local'` + `resultTrust: 'controlled-host'`；Host `passed` 只有对应 EvidenceBundle `ready`/`verified` 才能通过 Gate，`failed`/`cancelled`/`timed_out`/`provider_error`/`blocked`/`not_run` 都必须阻断 Gate。
- 取消、超时、断线、重试、部分 artifact 和 provider error 都要保存可审计状态。
- 不增加生产 npm 依赖，不把 HostExecution contract 扩散成第二套 TestRun 模型。
- HostExecution 记录必须有稳定 `attemptGroupId`；重试后 Action Queue 只显示该逻辑执行组的最新行动项。
- ActionItem 通过 `titleKey`、`reasonCode`、`reasonArgs` 支持中英文；API 不直接传输单一语言展示文案。
- `GET /api/action-queue?limit=1..50` 只读，排序键固定；旧 `GET /api/board` 的 `reminders` 只通过 `toLegacyReminders` 兼容投影提供。
- `priorityRank`、`statusRank`、`dueAt` 的排序方向和 `critical/high/medium/low` 映射以 Action Queue 设计规格为准；数据源故障返回 `503`，不能返回空队列掩盖故障。
- 现有项目级 `executionProfiles` 中没有 `kind` 的记录保持 local 语义；Native Host profile 使用 `kind: 'host'`，不得把 profile 嵌套到 `qualityTasks`，也不得让 Host flow 改写现有 local runner 的命令边界。

## Review Focus

- Provider error、imported-summary、未 finalize artifact 和缺少 provenance 不能产生 PASS；由 HostExecution/Evidence/Gate 测试覆盖。
- 同一逻辑执行组的 retry 不得在 Action Queue 中留下旧 terminal action；由 Action Queue 单测和 API 测试覆盖。
- `quality.host-execution.updated` 与 `quality.test-run.updated` 必须分别刷新正确的数据；由 SSE/API 测试覆盖。
- 英文界面不能显示中文 title/reason；由双语 Playwright 场景覆盖。
- `limit` 越界、同优先级 tie-breaker、数据源错误和 SSE hello 重连必须可预测；由 API/浏览器测试覆盖。

- [ ] **Step 1: Write failing Action Queue tests**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { buildActionQueue, toLegacyReminders } from '../../server/action-queue.js';
import { makeProject, makeTestRun, makeGate } from '../helpers/quality-fixtures.js';

const NOW = new Date('2026-09-23T00:00:00.000Z');
const fixtureProjects = [
  makeProject({
    id: 'project_1',
    title: 'Pay',
    testruns: [makeTestRun({ id: 'run_1', projectId: 'project_1', status: 'failed', errorCode: 'provider_error' })],
    gates: [makeGate({ id: 'gate_1', projectId: 'project_1', verdict: 'BLOCK', status: 'evaluated' })],
  }),
  makeProject({
    id: 'project_2',
    title: 'Orders',
    milestones: [{ id: 'milestone_1', title: 'UAT', dueDate: '2026-09-24', status: 'open' }],
  }),
];

Assert the returned items against the complete contract (`kind`, `priority`, `status`, `actionRequired`, `titleKey`, `reasonCode`, `reasonArgs`, `source`, and `target`), and separately assert that `toLegacyReminders()` preserves the existing milestone `days` field without inventing that field for gate/workflow items.
const projectWithRetriedHostExecution = makeProject({
  id: 'project_retry',
  hostExecutions: [
    { id: 'old_host', testRunId: 'old_run', attemptGroupId: 'group_1', status: 'failed', updatedAt: '2026-09-22T00:00:00.000Z' },
    { id: 'new_host', testRunId: 'new_run', attemptGroupId: 'group_1', status: 'running', updatedAt: '2026-09-23T00:00:00.000Z' },
  ],
  testruns: [
    makeTestRun({ id: 'old_run', projectId: 'project_retry', status: 'failed', hostExecutionId: 'old_host' }),
    makeTestRun({ id: 'new_run', projectId: 'project_retry', status: 'running', hostExecutionId: 'new_host' }),
  ],
});
const actionItems = buildActionQueue(fixtureProjects, { now: NOW, limit: 50 }).items;

test('orders blocking execution actions before due reminders and uses stable tie-breakers', () => {
  const result = buildActionQueue(fixtureProjects, { now: NOW, limit: 50 });
  assert.deepEqual(result.items.map((item) => item.id), [
    'gate_block:project_1:gate_1',
    'run_failed:project_1:run_1',
    'milestone_due:project_2:milestone_1',
  ]);
  assert.equal(result.items[1].reasonCode, 'provider_error');
});

test('hides superseded terminal attempts after a retry starts', () => {
  const result = buildActionQueue(projectWithRetriedHostExecution, { now: NOW, limit: 50 });
  assert.equal(result.items.some((item) => item.entityId === 'old_run'), false);
  assert.equal(result.items.find((item) => item.entityId === 'new_run')?.status, 'in_progress');
});

test('legacy reminders keep the existing field shape', () => {
  const reminders = toLegacyReminders(actionItems, { now: NOW });
  const milestone = reminders.find((item) => item.type === 'milestone');
  const gateOrWorkflow = reminders.find((item) => item.type !== 'milestone');
  assert.deepEqual(Object.keys(milestone).sort(), ['date', 'days', 'id', 'projectId', 'projectTitle', 'severity', 'title', 'type']);
  assert.equal('days' in gateOrWorkflow, false);
  assert.deepEqual(Object.keys(gateOrWorkflow).sort(), ['date', 'id', 'projectId', 'projectTitle', 'severity', 'title', 'type']);
});
```
