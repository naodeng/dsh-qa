# DSH QA Workbench 0.4.1 Implementation Plan（Harness 0.1.6 兼容性加固）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不重写 Workbench 前端的前提下，验证并加固 dsh-qa 与 Harness `dsh-v0.1.6-alpha.1` 的 RPC、Session、Workbench 主路径，并产出可审计的兼容性证据。

**Architecture:** 保留当前 slash RPC 和 `session/follow` transport；把 request/follow envelope 提取为可测试的纯契约；本地测试和真实 Harness host smoke 分开。0.4.1 不迁移 Panel API，也不继续扩大 DOM 注入架构。

**Tech Stack:** Node.js ESM、原生浏览器 JavaScript、WebSocket、Node `node:test`、Playwright、真实 DeepSeek Harness `dsh-v0.1.6-alpha.1`（仅 opt-in host smoke）。

**Spec:** `docs/quality-workbench/2026-09-15-requirements.md` §4.1；`docs/quality-workbench/2026-09-15-technical-design.md` §3；`docs/quality-workbench/2026-09-15-harness-compatibility.md`。

## Global Constraints

- 不把静态契约、独立 Workbench E2E 或 Harness 旧版本结果写成 `dsh-v0.1.6-alpha.1 tested`。
- 保持 `agentPresets/list`、`session/list`、`session/modelCatalog`、`skills/list`、`commands/list`、`session/follow` 和 `session/prompt` 的 slash endpoint 语义。
- `session/follow` 读取 `snapshot.records` 和 `cursor`；不得恢复 `snapshotEvents`、`eventAt` 或 `ownEvents`。
- 不重新引入 Remote Pair、旧 dot-style API Proxy 或插件内第二套 model/session 数据。
- 标准 `npm test` 不依赖 DSH 登录、真实模型、API Key 或外部 Harness；host smoke 必须是显式 opt-in 命令。
- 所有 `NOT_RUN`、`BLOCKED`、`FAILED` 状态都保留在矩阵中，不能用通过的本地测试覆盖。
