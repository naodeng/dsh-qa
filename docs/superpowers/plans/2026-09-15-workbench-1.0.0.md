# DSH QA Workbench 1.0.0 Implementation Plan（AI-Native QA Workbench）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 0.4.1–0.7 的 Harness 接入、官方 Panel、原生执行和 Quality Intelligence 收束成一条可观察、可审批、可终止的 AI-Native QA Workbench 主路径。

**Architecture:** Panel 负责宿主入口，Workbench iframe 负责产品 UI，QualityTask/TestRun/Evidence/Gate 继续作为事实主模型，AgentRun 只编排白名单领域动作并保存审计引用。1.0 建立受控 Agent foundation，不承诺完全自治或自动发布。

**Tech Stack:** Node.js ESM、现有 HTTP/SSE/JSON store、官方 Harness Panel/Slot API、HostExecution adapters、Quality Intelligence、Playwright、Node `node:test`。

**Spec:** `docs/quality-workbench/2026-09-15-requirements.md` §4.5；`docs/quality-workbench/2026-09-15-solution-design.md` §3.5；`docs/quality-workbench/2026-09-15-technical-design.md` §7。

**Depends on:** 0.4.1–0.7 的适用验收项全部有证据；未完成项必须在 release decision 中明确为 `blocked` 或 `not run`，不能用 1.0 文档覆盖。

## Global Constraints

- Agent 不直接修改 JSON store，不直接执行任意 shell、MCP 或生产动作。
- 所有 Action 声明 `tool`、`risk`、`requiresApproval`、输入引用和结果引用。
- 发布、Gate exception、风险接受、生产执行和安全敏感动作必须停在 `approval_required`。
- 任何未知、冲突、未执行、证据过期或 provenance stale 状态都不能变成 PASS。
- 1.0 仍保持零生产依赖、独立模式降级和中英文 UI。

### Task 1: Define the bounded AgentRun state machine

**Files:**
- Create: `server/agent/runtime.js`
- Create: `server/agent/actions.js`
- Create: `test/unit/agent-runtime.test.js`

**Interfaces:**
- `startAgentRun(project, input) → agentRun`
- `planAgentAction(agentRun, action) → agentRun`
- `completeAgentAction(agentRun, result) → agentRun`
- `requestAgentApproval(agentRun, action) → agentRun`
- `stopAgentRun(agentRun, reason) → agentRun`

- [ ] **Step 1: Write failing state tests**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { startAgentRun, planAgentAction, requestAgentApproval, completeAgentAction } from '../../server/agent/runtime.js';

test('agent run stops for approval before a release action', () => {
  const run = startAgentRun({}, { projectId: 'project_1', goal: 'assess release', maxSteps: 3, budget: 10 });
  const planned = planAgentAction(run, { type: 'release', tool: 'release', risk: 'high', requiresApproval: true });
  const waiting = requestAgentApproval(planned, planned.actions[0]);
  assert.equal(waiting.status, 'approval_required');
  assert.equal(waiting.actions[0].status, 'approval_required');
});

test('completed low-risk action records result without changing Gate verdict', () => {
  const run = startAgentRun({}, { projectId: 'project_1', goal: 'inspect evidence', maxSteps: 2, budget: 10 });
  const planned = planAgentAction(run, { type: 'inspect_evidence', tool: 'evidence.read', risk: 'low', requiresApproval: false });
  const completed = completeAgentAction(planned, { status: 'ok', evidenceRefs: ['ev_1'] });
  assert.equal(completed.actions[0].status, 'completed');
  assert.equal('verdict' in completed, false);
});
```

## Out of scope for 1.0.0

- Fully autonomous release or production deployment.
- Multi-agent orchestration as a required path.
- Quality Obligation graph, Graph Database, universal Adapter SDK or project-wide Policy Engine.
- Real multi-user RBAC, cloud distributed execution and external defect system automation.
