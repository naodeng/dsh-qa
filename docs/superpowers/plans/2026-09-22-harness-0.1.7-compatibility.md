# Harness 0.1.7 Compatibility Optimization Implementation Plan

> **For agentic workers:** Execute this plan in the current workspace with TDD and verification before completion.

**Status:** Bundle implementation, local verification, and the authenticated `qa` bundle Host Smoke are complete (`6 passed`); `quality-control` runtime verification and publication remain outside this task.

**Goal:** Make the dsh-qa plugin and its optional quality-control preset installable through DeepSeek Harness 0.1.7's declarative profile-bundle model.

**Architecture:** The main `dsh-qa` bundle will declare the `qa` agent preset through `@deepseek-ai/dsh-agent-preset`. The optional `quality-control` preset will become its own small local bundle package, installed into the active profile with `dsh plugin`; both legacy directory-copy scripts will become profile-aware bundle installers. Existing Session and standalone workbench code remain unchanged; the native Panel popout received one targeted lifecycle fix after the first real 0.1.7 smoke.

**Tech Stack:** Node.js ESM, YAML bundle patches, Bash installers, Node built-in `node:test`, Markdown documentation.

**Spec:** `docs/quality-workbench/2026-09-22-harness-0.1.7-impact-assessment.md`

## Global Constraints

- Keep the project ESM, Node 18+, and zero production dependencies.
- Preserve the current `qa` plugin composition and existing unrelated work.
- Do not claim real Harness 0.1.7 compatibility for a bundle without an authenticated host smoke run for that bundle.
- Keep standalone mode independent from Harness provider configuration.

## Review Focus

- The published main package must expose the `qa` bundle patch and must not rely on `.agent-presets` directory discovery; tests assert both the package manifest and patch shape.
- The optional quality-control bundle must be installable independently and must use `prefix` plus `workflow-ptc`; tests assert its package, patch, and source composition.
- Installer dry runs must be side-effect free and must target the active profile rather than copying files into a legacy directory; tests assert the command contract and no legacy path.
- Bilingual installation guidance must describe the same profile-bundle workflow; tests and diff review cover both README files.
