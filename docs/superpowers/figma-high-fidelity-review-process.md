# Figma 页面高保真审查流程

状态更新日期：2026-11-24

本文用于继续审查 DSH-QA 的 Figma 页面。先完成原型、差异修复和逐页确认，再开始前端开发。

## 项目与审查边界

- 目标文件：[DSH-QA](https://www.figma.com/design/1M4DD2SUwJdbBqhWX1c9B9/DSH-QA?node-id=0-1)
- 组件参考：[Arco Design Pro 2.0](https://www.figma.com/design/3QNuk7vINQ4ag4lal3y4yz/Arco-Design-Pro-2.0-%E8%AE%BE%E8%AE%A1%E8%B5%84%E6%BA%90--Community-?node-id=0-1)
- Figma 的读取、修改和验收只使用已安装的 Figwright 插件。
- 复用 Arco 文件中合适的组件和模式。没有依据时不要另造视觉样式。
- 原型使用可编辑图层。不要把整页截图当成交付稿。
- 保留现有文案、信息架构和操作功能。原型不得暗示代码当前没有的能力已经实现。
- 完成逐页审查和确认前，不开始前端 UI 重构。
- 当前画板目标：桌面 2560×1440、1920×1080 和 1440×900 对比画板，平板 1024×768，手机 390×844。需要覆盖浅色和深色状态。原型中已有的画板仍须逐一核验，不能因画板存在就视为通过。

## 每页审查流程

按页面顺序逐页执行以下步骤。每页完成后记录差异、修复、残余问题和验收证据。

1. 在 Figma 打开 DSH-QA 文件并启动 Figwright。用 `ping` 确认插件已连接目标文件。
2. 列出当前页的全部顶层画板、流程入口和状态。核对页面名、尺寸、明暗主题和数据状态。
3. 在 Arco 参考文件找到相同用途的原生组件或页面模式。先复用组件，再检查本项目所需的文案、数据和功能适配。
4. 对齐对比条件：使用相同 Frame 尺寸、缩放比例、页面状态和数据。先比导航和页面边界，再比布局、组件、文字、图标和状态。
5. 检查按钮、标签、徽标、正文、图标、侧边导航、顶部导航、面包屑、表格、分页、筛选、弹层和所有空、加载、错误状态。相同语义使用相同组件和 Token。不同语义须能从样式和文案区分。
6. 按严重程度记录差异。修复有证据支持的问题，不添加无依据的视觉样式或功能。
7. 修改后重新导出同一画板截图。重新读取原型连线，确认布局没有溢出，并检查其他页面是否受到共享组件修改的影响。
8. 在该页面的 Dev Mode 注释或本文状态表中记录修复结果、未解决项和证据。确认页面后再进入下一页。

### 严重程度

- **Critical**：阻断主流程、导致错误操作或关键数据误读，或让主要内容无法访问。
- **Major**：核心交互缺失，主要信息被截断，关键组件不符合参考，或不同页面出现明显不一致。
- **Minor**：不阻断任务的间距、对齐、次级图标或文案细节偏差。

先处理 Critical，再处理 Major，最后处理 Minor。每条问题都要能指出对应画板、组件或交互状态。

## 逐页通过条件

只有同时满足以下条件，才能将页面标记为“已确认，可进入开发”。

- 所有目标视口和浅色、深色画板均已检查，缺失的必要画板已补齐。
- 关键组件与 Arco 参考一致，或已记录有依据的适配原因。
- 主路径、返回路径、错误路径、空状态、加载状态和分页都已检查。
- 数据来源明确。模拟数据标注为模拟数据，不冒充真实业务记录。
- 截图在相同 Frame、缩放、状态和数据条件下完成复核。
- 原型关键连线已在 Figwright 中读回，并在 Figma 演示模式中实际走通。
- Critical 和 Major 差异已修复。残余 Minor 问题已经记录并说明影响。
- 用户已确认该页面。构建或自动化测试不能代替视觉验收和用户确认。

- 看板移动端显示了局部任务卡，但没有完整任务列表和分页。现有任务总数、状态统计和可见样本必须先核对，不能通过编造记录填满页面。

## 继续工作的顺序

按以下顺序继续，并在每页完成后更新上面的状态表。

1. 完成 05 · 工作日历的创建、详情、删除、日期选择和视图切换原型。用演示模式走通后，再检查桌面、平板、手机和两种主题。
2. 完成 03 · 项目看板的完整列表、分页和统计数据核对。确认已有模拟数据和空状态表达清楚。
3. 完成 02 · DSH 测试对话的关键交互和连接状态。
4. 逐页审查 01 · 测试首页与 04 · 项目详情。优先核对共享导航，再审查分页和实体跳转。
5. 审查 06 · QA Skills 和 07 · 空状态与弹层，并回连到实际来源页面。
6. 最后统一审查 00 · Arco Design System，核对每个业务页所用组件与 Token。
7. 完成所有页面后，整理最终差异和残余问题，请用户逐页确认。用户确认前不要启动 UI 开发。

## 继续操作前的检查

每次开始工作时：

1. 打开 DSH-QA 文件，启动 Figwright，并确认当前连接的文件名。
2. 用 Figwright 检查当前页面和画板，不依赖旧截图猜测实际状态。
3. 检查 Git 状态。只提交本次任务文件，保留其他已有改动。
4. 按本文的通过条件完成当前页面后，再更新状态表和续做顺序。
