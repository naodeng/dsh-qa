# DSH QA Workbench Quiet Studio UI Redesign

> 状态：Draft for review
>
> 视觉方向、首页结构和组件语言已通过 UI demo 确认；本文用于实现前的最后一次范围与交互确认。

## 1. 已确认的设计决策

本次改造允许彻底更换视觉风格，但保留现有 QA 工作台的业务信息架构、URL、DSH 会话接入和数据契约。

- 视觉风格：`Quiet Studio / 安静工作室`。
- 首页结构：`Focus Canvas / 聚焦画布`。
- 组件语言：白色内容面、冷灰页面底、黑墨色文字、绿色成功状态、橙色风险状态；使用薄边界和轻阴影，不使用渐变、发光或厚重卡片阴影。
- 品牌区：左侧 logo 与 `QA 工作台` 同时展示当前版本号；版本号是可点击入口。
- 设置入口：右上角使用对比度足够的设置按钮，打开设置弹窗。
- 设置内容：仅保留语言和关于信息；主题与工作区宽度预设不再作为用户设置。
- 版本历史：从品牌区版本号打开，按版本发布时间倒序展示，支持分页和 GitHub 详细更新链接。
- 双语规则：中文界面只显示中文描述，英文界面只显示英文描述；禁止以另一语言的摘要作为展示兜底。

## 2. 目标与非目标

### 2.1 目标

- 降低当前页面的视觉噪声，让用户首先看到今天需要处理的 QA 风险、排期和项目状态。
- 在桌面宽屏上建立清晰的「顶部全局工具栏 → 收窄导航 → 主工作面」层级，在窄屏上自然收缩而不是依赖横向滚动。
- 统一首页、DSH 对话、项目看板、日历、设置弹窗、版本历史和项目详情的控件形态。
- 保持所有现有动态行为可用：项目创建、项目切换、DSH 对话、看板拖动、日历操作、Skill 安装、项目详情、版本检查和语言切换。
- 提升设置按钮、版本提醒、焦点状态和状态色的可读性及键盘可操作性。

### 2.2 非目标

- 不新增质量实体、项目字段、DSH RPC 方法或新的持久化模型。
- 不改变 DSH 会话、模型、技能、命令和权限的来源；这些仍由 DSH 当前会话负责。
- 不改变现有页面入口和主要业务路由，不把首页改造成新的平行产品。
- 不在本版继续提供主题切换、主题持久化或设置弹窗中的工作区宽度预设。
- 不把项目文件夹能力从项目创建和项目详情中移除；本次只移除设置弹窗里的工作区宽度设置。

## 3. 页面与信息架构

### 3.1 全局壳层

```text
顶部工具栏
  ├── 品牌 logo + QA 工作台 + 当前版本（可点击）
  ├── 全局搜索
  ├── DSH 连接状态 / 返回 DSH
  └── 设置

主体
  ├── 收窄主导航（首页、对话、看板、日历、Skill）
  └── 主工作面
```

顶部品牌区在导航收起时仍保持可识别；版本号不依赖主题色，使用等宽字体和明确的点击反馈。

### 3.2 Focus Canvas 首页

首页按以下优先级排布：

1. 页面标题、日期上下文和主要动作（进入 DSH 对话、新建项目）。
2. 四个轻量指标：在办项目、七日内里程碑、已逾期里程碑、未关闭缺陷。
3. 「需要你处理」队列作为最大主面板，保留风险、截止时间、项目和 CTA。
4. 右侧「接下来 7 天」日程与里程碑。
5. 「在办项目」列表，按最近活动排序，点击进入项目工作区。
6. 最近动态和 DSH 辅助信息作为低优先级辅助内容。

指标直接映射现有 `GET /api/board` 响应中的 `stats`：`activeProjects`、`dueSoonMilestones`、
`overdueMilestones` 和 `openDefects`。本次视觉改造不虚构“当前周期完成度”或没有数据
来源的“待处理风险”指标，也不改变 API 形状；改造重点是布局和渲染层级。

### 3.3 对话、看板和日历

- DSH 对话保留项目列表、聊天主区和项目雷达，但通过更轻的边界、统一的标题栏和一致的输入框降低三栏之间的割裂感。
- 看板保留列、卡片拖动和项目详情入口；卡片状态使用状态色和短标签，不使用整张彩色背景。
- 日历保留月视图、选中日期、日程和里程碑；日期选中态使用黑墨色实心标记，风险/逾期使用橙色或红色小标记。
- 项目详情、抽屉、能力弹窗和新建项目弹窗统一使用 Quiet Studio 的 modal、drawer、surface 和 form token。

## 4. 视觉系统

### 4.1 颜色与层级

固定为以下 Quiet Studio CSS custom properties，UI demo 中的颜色和层级以这些 token 为准：

| 语义 | 用途 | 方向 |
| --- | --- | --- |
| `--page` | 页面背景 | `#e9eded` |
| `--surface` | 面板、弹窗、输入区 | `#ffffff` |
| `--surface-soft` | 次级面、表头、输入底色 | `#f7f8f8` |
| `--ink` | 标题、主要操作 | `#17212b` |
| `--muted` | 说明、次级信息 | `#697783` |
| `--faint` | 日期、辅助标签 | `#879399` |
| `--line` | 分隔线和边框 | `#d6dfe1` |
| `--line-soft` | 内容分隔线 | `#e8eded` |
| `--teal` | 成功、连接、当前状态、链接 | `#167b70` |
| `--teal-soft` | 成功状态底色、轻量选中态 | `#eff8f5` |
| `--amber-ink` | 临期、风险、待判断文字 | `#8f4c13` |
| `--amber-soft` | 临期、风险、待判断底色 | `#fff3e7` |
| `--danger` | 逾期、错误、破坏性操作 | `#b4232e` |
| `--danger-soft` | 错误和逾期底色 | `#fcecee` |
| `--radius-control` | 按钮、输入框、导航项 | `7px` |
| `--radius-surface` | 面板、卡片 | `9px` |
| `--radius-modal` | 弹窗、抽屉 | `12px` |
| `--shadow-surface` | 面板层级 | `0 4px 16px rgba(23, 33, 43, .06)` |
| `--shadow-modal` | 弹窗层级 | `0 18px 32px rgba(23, 33, 43, .12)` |

所有文本和控件需要满足可读对比度；设置按钮必须在浅色页面背景上清晰可见。状态颜色不能单独承担语义，需同时保留文字或图标。

### 4.2 形状、间距和字体

- 面板使用小到中等圆角、1px 边框和非常轻的阴影；不使用大面积玻璃效果。
- 标题使用系统 UI 字体；版本号、项目编号和版本历史版本列使用等宽字体。
- 通过 4/8px 间距节奏统一面板内部留白、按钮高度和表单间距。
- 动画只用于弹窗、选中态和拖动反馈；尊重 `prefers-reduced-motion`。

### 4.3 交互状态

所有按钮、导航项、输入框、分隔拖拽器和版本入口都需要有 `:hover`、`:focus-visible`、`[aria-disabled]` 或 disabled 的明确状态。键盘焦点不能依赖低对比度的默认 outline。

### 4.4 弹窗与抽屉可访问性

`modalShell` 和抽屉使用统一的交互契约：

- 弹窗根节点使用 `role="dialog"`、`aria-modal="true"` 和稳定的 `aria-labelledby`。
- 打开后把焦点移到关闭按钮或第一个可操作控件；关闭后恢复到触发按钮。
- `Escape` 关闭弹窗；点击 backdrop 关闭只作为鼠标辅助路径。
- 弹窗打开期间禁止背景内容获得焦点，并锁定页面滚动；抽屉保持同样的焦点边界。
- 设置弹窗和版本弹窗的关闭按钮必须有本地化 `aria-label`，分页按钮必须反映 disabled 状态。
- reduced-motion 下不依赖动画完成来设置可交互状态。

## 5. 设置弹窗

设置按钮点击后打开单一设置弹窗，内容固定为两个区块：

### 5.1 语言

- 提供 `中文` 和 `English` 切换。
- 切换后立即刷新静态页面文案、动态区域、设置弹窗和版本历史；不刷新页面、不丢失当前视图或项目选择。
- 语言按钮使用 `aria-pressed`，当前语言有清晰的选中态。

### 5.2 关于

展示：

- 当前安装版本。
- 最新版本及是否有新版本。
- 兼容的 DSH 版本。
- 项目 GitHub 仓库，直接展示可识别的仓库地址并可点击。
- 项目官网，直接展示当前语言对应的官网 URL 并可点击；不再显示“打开链接”这类替代文字。

主题选择、主题说明、主题 CSS 变体、`data-theme` 运行时依赖和设置弹窗中的工作区宽度预设全部移除。旧的主题值读取后忽略即可；`dsh-qa-layout` 仍用于保存直接拖拽/收起状态，不属于设置弹窗的宽度预设，也不应被清除。

## 6. 版本入口与版本迭代弹窗

### 6.1 版本提醒

- 品牌区使用 `/api/app-info` 的 `currentVersion` 和 `latestVersion`。
- 当当前版本低于最新版本时，在版本号后显示红色 `*`；无新版本或用户已查看最新版本后隐藏。
- 用户首次点击版本号即视为查看一次，使用 `localStorage` 记录已经查看的最新版本；同一最新版本后续点击不再显示红色 `*`。
- 点击版本号仍然打开版本迭代弹窗，标记已查看不能阻止弹窗打开。

### 6.2 版本迭代弹窗

每条记录至少包含：

- 版本号。
- 更新日期。
- 当前语言对应的简短更新描述。
- “查看详细更新 ↗”链接，指向 GitHub Release/tag。

记录按发布时间倒序排列；同一发布时间按 semver 倒序，仍相同时按版本号稳定排序。
服务端返回 `publishedAt`（可精确排序的 ISO 时间）和用于展示的 `date`（`YYYY-MM-DD`）；
本地 CHANGELOG 只有日期时使用当天 `00:00:00Z`，GitHub Release 优先使用
`published_at`。前端不再重新按版本号排序，只展示接口顺序。保留现有分页能力，页大小
固定为当前实现的 5 条，空数据、加载中和加载失败使用不同的本地化状态。

版本数据仍来自 `GET /api/app-info`，不在前端复制一套 release 数据。接口记录契约为：

```js
{
  version: '0.5.2',
  date: '2026-09-23',
  publishedAt: '2026-09-23T00:00:00.000Z',
  summaryZh: '中文摘要',
  summaryEn: 'English summary',
  detailUrl: 'https://github.com/naodeng/dsh-qa/releases/tag/v0.5.2'
}
```

中文只显示 `summaryZh`，英文只显示 `summaryEn`。服务端合并 CHANGELOG、GitHub 和 tag
数据时不得用另一语言摘要填充缺失字段；GitHub 的英文 body 只能写入 `summaryEn`，不能
同时写入 `summaryZh`。如果当前语言摘要缺失，前端显示当前语言的“暂无中文更新摘要”或
“No English summary available”，不跨语言 fallback。

### 6.3 加载失败与重试

版本弹窗维护 `loading`、`ready`、`empty`、`error` 四种状态：

- `loading`：显示本地化加载提示，分页按钮 disabled。
- `ready`：显示当前页记录和可用分页。
- `empty`：请求成功但没有记录，显示空状态。
- `error`：请求失败，显示本地化错误说明和“重试”按钮；重试成功后回到 `ready`，失败仍停留在 `error`。

请求失败不能继续显示“正在读取版本记录”，也不能把失败误判为空数据。

## 7. 双语实现约束

- 新增和重写的静态文案必须进入 `public/i18n.js`，不能只在 `index.html` 或 `app.js` 写中文。
- 动态标题、按钮、状态、空状态、分页和 aria 文案都通过 `t()` 或现有语言辅助函数生成。
- 当前语言由 `currentLang()` 决定；不通过浏览器语言临时覆盖用户选择。
- 版本历史摘要必须由字段选择函数按语言选择，不使用跨语言 fallback；接口合并层和前端渲染层都要遵守这一点。
- E2E 需要分别覆盖中文和英文：设置区块、官网 URL、版本历史首条摘要、分页和关键导航文案不能出现相反语言的独占文案。

## 8. 实现边界与拆分

### 8.1 第一阶段：壳层和 token

- 重做 `public/style.css` 的 Quiet Studio 基础 token、顶部工具栏、窄导航、surface、button、modal、drawer 和响应式规则。
- 移除主题选择相关 CSS 变体、`body[data-theme]` 选择器、`data-theme` 属性和主题文案，固定为 Quiet Studio。
- 保留现有 DOM id 和事件入口，减少业务逻辑迁移风险。

### 8.2 第二阶段：首页与核心页面

- 将首页调整为 Focus Canvas 的指标、行动队列、7 日日程和项目列表层级。
- 统一对话、看板、日历、详情页和表单的组件样式。
- 保留面板收起/直接拖动等已有交互；不再通过设置弹窗提供宽度预设。`DEFAULT_LAYOUT`、`LAYOUT_RANGES` 和 splitter 事件属于直接操作，不视为已移除的设置功能。

### 8.3 响应式与导航细则

- `>= 1280px`：使用 64px 图标导航、完整 Focus Canvas 主工作面和双栏首页内容区。
- `768px–1279px`：保持图标导航；全局搜索可收缩为图标入口；首页内容区改为单列，项目列表保留横向字段但允许次级字段折叠。
- `< 768px`：导航、项目栏和项目雷达均可收起；对话页只保留一个主面板，项目栏和雷达以抽屉/覆盖层打开；首页指标为两列，行动队列优先，日程和项目列表纵向排列。
- `< 480px`：版本记录改为版本号/日期、摘要、详细链接三段纵向布局；所有主要按钮保持单行可读，不能依赖横向滚动。
- 收窄导航仍需为图标提供 `aria-label` 和 hover/focus tooltip；最近项目不能因导航收窄而丢失，移动端放入对话页项目抽屉。
- 至少用 Chromium 在 `1280×800`、`768×900` 和 `390×844` 验证首页、设置弹窗、版本弹窗和对话页。

### 8.4 第四阶段：设置、版本和双语

- 统一设置按钮的图标、尺寸、对比度和 focus 状态。
- 调整设置弹窗，删除主题/工作区宽度区块，只保留语言和关于。
- 修复官网直接展示 URL 的文案。
- 修复版本入口、红色 `*` 一次查看语义、版本历史分页和中英文摘要选择。
- 必须调整 `server/app-info.js` 的摘要合并、`publishedAt` 生成和发布时间排序逻辑，确保 `summaryZh` 和 `summaryEn` 不互相覆盖。

### 8.5 第五阶段：验证

- 更新受影响的 unit/API 和 Chromium E2E 断言。
- 验证中文/英文、独立模式/嵌入 DSH 模式、最新版本/过期版本、发布时间与版本号不一致的 release、缺少单语言摘要、空 release、分页 release、app-info 请求失败、窄屏和键盘操作。
- 运行项目要求的 `npm test`、`git diff --check`，并检查未引入 `.superpowers/` 预览产物或测试产物。

## 10. 设计自审

- 范围是否可控：是。改造限制在既有前端壳层、渲染文案和 app-info 元数据合并/排序规则，不引入新的业务模型；指标沿用现有 board.stats。
- 是否保留用户已确认的重点：是。Quiet Studio、Focus Canvas、设置/版本入口和双语规则均写入交互契约。
- 是否处理已知问题：是。设置按钮对比度、主题/宽度设置移除、官网直接展示、版本一次查看、发布时间排序、加载失败和语言泄漏均有明确方案。
- 是否存在兼容风险：有。旧主题值、已有 E2E 选择器和 `data-theme` 依赖需要在实现阶段逐项搜索并验证；直接拖拽布局状态和现有业务 DOM id 必须保留。
- 是否过度扩展：否。没有把 DSH 会话、质量实体或 Action Desk 逻辑并入此次视觉改造。
