# DSH QA Workbench 0.6.0：Native QA Execution & Action Desk 设计

> 状态：Draft for review
>
> 本文把旧路线中的 Action Desk 作为 Native QA Execution 的用户入口合并进
> `0.6.0`。它不改变质量事实、TestRun、EvidenceBundle 或 Gate 的所有权。

## 1. 决策与目标

`0.6.0` 保持 Native QA Execution 为主版本主题，同时增加 Action Desk 作为
执行状态和质量阻断项的 action-first 首页体验。发布标题建议使用：

```text
Native QA Execution & Action Desk
```

用户打开工作台后应能完成以下闭环：

1. 从已评审的 Execution Profile 预览并确认一次受控 Host Execution。
2. 在执行过程中看到 queued/running、失败、取消、超时和 provider error。
3. 在执行结束后知道 Evidence 是否已完成、是否需要人工处理。
4. 从首页的“需要你处理”队列直接跳到执行、证据、门禁、项目或 DSH 对话。

Action Desk 是质量事实的只读投影，不是第二套质量数据模型，也不负责计算或
修改 Gate verdict。

## 2. 当前基线与问题

当前首页已经有指标卡、日历、在办项目、最近动态和“需要你处理”区域；服务端
通过 `GET /api/board` 返回 `reminders`。现有提醒主要覆盖里程碑、项目流程和
待审批门禁，不能完整表达 Host Execution 的生命周期、Evidence 缺失或失败后
需要采取的动作。

当前 `0.6.0` Native QA Execution 计划已经定义：

```text
Execution Profile
  → HostExecution adapter
  → TestRun provenance
  → EvidenceBundle finalize + verify
```

如果没有统一的行动入口，执行状态会停留在项目详情内，用户仍需要自己寻找
失败运行、未完成证据和阻断门禁。因此，本版将 Action Desk 做成首页现有
attention panel 的规范化升级，而不是新增一个平行顶级页面。

## 3. 范围

### 3.1 本版包含

- 统一的 `ActionItem` 纯函数聚合器，读取现有项目、质量任务、TestRun、
  EvidenceBundle、Gate 和 Host Execution 状态。
- `GET /api/action-queue` 只读接口，默认返回最多 50 条、稳定排序的行动项。
- 首页以 Action Queue 作为“需要你处理”区域的唯一数据源；保留指标、日历、
  在办项目和最近动态等辅助区域。
- Host Execution 状态与 Action Queue 的映射：queued/running 可监控，failed、
  cancelled、timed_out、provider error、证据不完整需要处理。
- Gate `BLOCK`/`WARN`、待审批 Gate、确认阶段的关键风险、逾期/临期里程碑和
  既有流程提醒的聚合。
- Action Item 到项目详情、执行详情、Evidence、Gate 或 DSH 对话的安全跳转。
- 质量实体和 Host Execution 更新后的 SSE 刷新。
- 独立模式中的 fake adapter、Action Queue、API 和浏览器 E2E 覆盖；真实 Host
  evidence 与 fake evidence 分开记录。

### 3.2 本版不包含

- AI 失败解释、变更影响分析、回归推荐或 Gate 推荐；这些属于 `0.7.0`。
- 任意 Shell 执行、未登记的 MCP server、生产凭证或任意 Host mount。
- Action Desk 自己写入 TestRun、Evidence、Gate 或替代人工审批。
- 多 Agent 编排、自动发布和 Autonomous QE。
- 将旧 Action Desk 中的 `QA_SKILLS_ROOT` 路径治理强行绑定到执行主链路；如需
  保留，作为独立的低风险维护任务，不阻塞本版核心执行闭环。

## 4. 领域边界与数据流

```text
已登记 Execution Profile
        │
        ▼
HostExecution request / result
        │
        ├── TestRun status + provenance
        ├── staging artifacts
        └── EvidenceBundle finalize + verify
                    │
                    ▼
             trusted quality facts
                    │
                    ▼
          buildActionQueue(snapshot)
                    │
                    ├── GET /api/action-queue
                    └── 首页“需要你处理”
```

Host Execution 仍是执行事实的来源，TestRun 仍是运行事实的来源，EvidenceBundle
仍是证据完整性的来源，Gate 仍是确定性质量判断的来源。Action Queue 只读取这些
事实并生成短生命周期的显示项，不持久化一个新的 `actionItems` 数组。

### 4.1 ActionItem 最小契约

```js
{
  id: 'run_failed:project_1:run_1',
  kind: 'run_failed',
  priority: 'high',
  status: 'needs_action',
  projectId: 'project_1',
  entityId: 'run_1',
  title: 'Browser Use 执行失败',
  reason: 'provider 返回错误，尚未完成可信 Evidence',
  dueAt: null,
  source: { type: 'test-run', id: 'run_1' },
  target: { view: 'project-detail', tab: 'quality', entityId: 'run_1' }
}
```

约束如下：

- `id` 由 `kind + projectId + entityId` 稳定生成，用于去重和 E2E 定位。
- `target` 只能由服务端生成的有限 view/tab 组合构成，不能接受客户端提交任意
  URL 或命令。
- `status` 只描述用户界面动作状态：`needs_action`、`in_progress`、`blocked`。
  源事实变化后，Action Item 消失或变为另一项；不新增 resolved 存储。
- Action Queue 不包含客户端选择的 verdict，也不把 `passed` 显示为可信 PASS；
  只有现有 Evidence finalize/verify 和 Gate contract 才能决定质量结论。

### 4.2 最小行动类型

首批至少支持：

- `run_failed`
- `run_cancelled`
- `run_timed_out`
- `run_running`
- `evidence_incomplete`
- `gate_block`
- `gate_warn`
- `gate_approval`
- `quality_task_confirm`
- `milestone_overdue`
- `milestone_due`
- 现有项目流程提醒

运行类型和 provider 放入 source 或展示元数据中，不为每个 provider 创建一套
Action Item 模型。

## 5. API、事件和首页交互

### 5.1 Action Queue API

```text
GET /api/action-queue
→ {
    ok: true,
    items: ActionItem[],
    generatedAt: string
  }
```

接口只读；默认按 priority、阻断程度和 dueAt 排序，最多返回 50 条。无项目、无
行动项或数据源暂不可用时返回结构化空状态，不伪造成功执行结果。

现有 `GET /api/board` 和 `reminders` 保留兼容形状；内部由同一个聚合边界提供
数据，避免首页和旧消费者各自实现一套排序与提醒逻辑。

### 5.2 SSE 刷新

以下事件需要触发 Action Queue 重新拉取，并按 300ms 防抖合并刷新：

- `quality.task.updated`
- `quality.test-run.updated`
- `quality.evidence.updated`
- `quality.gate.updated`
- `quality.host-execution.updated`

Host Execution 如果没有单独持久化记录，可以只通过现有 `quality.test-run.updated`
表达状态；实现计划需要在 API 与事件测试中固定一种方式，不能让前端猜测。

### 5.3 首页

- 继续使用当前 `#dashboard-reminders` 区域，不新增 Action Desk 顶级导航项。
- 将其升级为 canonical Action Queue 渲染器，展示 priority、status、reason、
  project 和 CTA。
- 指标卡、日历、在办项目和最近动态保留，但视觉优先级低于需要处理队列。
- queued/running 只显示可监控状态；失败、超时、证据不完整和 Gate BLOCK 显示
  明确动作按钮。
- 空状态说明“当前没有需要处理的事项”，不能用 `PASS` 或绿色成功语义代替。
- 中英文 key 必须成对提供；独立模式显示能力不可用时的 `NOT_RUN` 或 `BLOCKED`
  边界。

## 6. 实施顺序

1. **Action Queue contract**：创建纯函数和 ActionItem fixture，覆盖稳定 ID、
   priority、状态映射和现有 reminder 兼容投影。
2. **API boundary**：增加 `GET /api/action-queue`，验证空状态、排序、limit、
   未知/越界来源和不写 Store。
3. **Host Execution integration**：完成当前 0.6 adapter、TestRun provenance、
   Evidence finalize/verify，并发出统一状态事件。
4. **Homepage integration**：将“需要你处理”接到 canonical queue，增加 CTA、
   status 和中英文空/错误状态。
5. **End-to-end verification**：fake adapter 证明执行到 Evidence 的闭环；浏览器
   E2E 证明首页刷新和跳转；真实 Host smoke 单独记录 provider evidence。

## 7. 验收标准

- `ActionItem` 聚合器对同一输入稳定、无副作用、可单测。
- API 返回结构固定，默认最多 50 条，重复调用不产生 Store 写入。
- Host Execution 的失败、取消、超时、断线、重试和 Evidence 不完整都能在首页
  产生正确的行动状态。
- `Gate BLOCK/WARN`、待审批 Gate、逾期/临期里程碑和既有流程提醒不回退。
- 首页无需整页刷新即可在相关 SSE 后更新队列。
- 每个行动项能跳到正确的项目详情 Tab 或 DSH 对话上下文。
- provider error、imported-summary、未 finalize artifact 或缺少 provenance 均不
  能产生 `PASS`。
- 通过 `npm run test:unit`、`npm run test:e2e`、`npm test` 和 `git diff --check`；
  fake adapter 与真实 Host smoke 的证据分别记录。

## 8. 风险与取舍

| 风险 | 缓解 |
| --- | --- |
| 0.6 变成两个大版本拼接 | Action Desk 只做只读投影和首页入口，执行与证据仍是主线 |
| 首页出现两套提醒 | 以 `buildActionQueue` 为唯一聚合边界，旧 reminders 只做兼容投影 |
| Action Queue 被误解为质量结论 | UI 显示 action/status/reason，不显示伪造的 PASS；Gate 继续独立计算 |
| Host provider 状态无法刷新 | 统一 SSE 事件并覆盖事件重连后的重新拉取 |
| 旧 Action Desk 范围继续膨胀 | Skills roots、AI 建议、变更分析和回归推荐留在独立版本/任务 |
